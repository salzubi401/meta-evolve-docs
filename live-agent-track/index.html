    Bounded live-agent track

    This track is optional, paid, and capped at 12 provider calls:

    Exercise Provider Model Maximum calls
    Repository proposal Claude claude-sonnet-5 1
    Repository proposal Codex gpt-5.4-mini 1
    Experience A/B Claude claude-sonnet-5 4
    Held-out skill evolution Claude claude-sonnet-5 6
    Total 12

    The environment variables below are explicit paid-work markers. The repository's credentialed drift tests require them and CI never sets them. The example scripts themselves do not inspect the variables; running each shown command is the final consent boundary. Stop after any exercise without invalidating the earlier observations.

    1. One repository proposal per provider

    Both commands use the same SourceTree task, evaluator, one-trial budget, Greedy policy, and pull declaration through the common proposer seam.

    Claude proposal

    • Prerequisites: uv sync --extra claude; authenticate Claude Code through an existing login or ANTHROPIC_API_KEY.
    • Opt-in marker: META_EVOLVE_LIVE_CLAUDE=1.
    • Provider and model: Claude, claude-sonnet-5.
    • Call ceiling: one session.
    • Variability: candidate bytes, token use, tool sequence, latency, and success can change between runs.
    • Confounders: Claude's native tools, approval profile, process environment, adapter timeout, and provider service state.
    META_EVOLVE_LIVE_CLAUDE=1 uv run --extra claude \
  python examples/06_sdk_coding_agent/main.py --provider claude

    Codex proposal

    • Prerequisites: uv sync --extra codex; run codex login and confirm it created a regular file-backed auth.json.
    • Opt-in marker: META_EVOLVE_LIVE_CODEX=1.
    • Provider and model: Codex, gpt-5.4-mini.
    • Call ceiling: one session.
    • Variability: candidate bytes, token use, tool sequence, latency, and success can change between runs.
    • Confounders: Codex's native tools, approval profile, private-home copy, inherited environment, writable temporary paths, and provider service state.
    META_EVOLVE_LIVE_CODEX=1 uv run --extra codex \
  python examples/06_sdk_coding_agent/main.py --provider codex

    Compare only the shared facts: both proposers receive the same declared task and their captured candidate is evaluated independently. Do not infer parity in quality, tools, tokens, cost, compute, containment, interruption, or wall time. The canonical examples/06_sdk_coding_agent/main.py owns these declarations.

    2. Claude experience A/B

    • Prerequisites: the Claude setup above, including SDK support for the in-process experience server.
    • Opt-in marker: META_EVOLVE_LIVE_CLAUDE=1.
    • Provider and model: Claude, claude-sonnet-5.
    • Call ceiling: four sessions: at most two trials in each of two arms.
    • Variability: either arm may pass early; outputs, tokens, latency, and tool use vary. The deterministic grader does not.
    • Confounders: one task and one hidden house convention; both arms use fresh sessions and an equal 12-turn ceiling, but provider state remains uncontrolled.
    META_EVOLVE_LIVE_CLAUDE=1 uv run --extra claude \
  python examples/12_experience_ab/main.py

    Read attempts, trials-to-first-pass, tokens, and pull counters together. A tie after real reads is a null result: experience made no measured difference. A tie with zero reads means the capability was unused, so the run did not test whether read experience helped. The examples/12_experience_ab/README.md contains the live transcript, controlled eight-repetition measurement, and its limits. The same report is driven without credentials by tests/test_experience_ab_example.py.

    3. Claude held-out skill evolution

    • Prerequisites: the Claude setup above.
    • Opt-in marker: META_EVOLVE_LIVE_CLAUDE=1.
    • Provider and model: Claude, claude-sonnet-5.
    • Call ceiling: six sessions: three outer candidates, each scored on two held-out episodes.
    • Variability: episode responses decide candidate scores, so the winning skills and stopping point can change even with the same random seed.
    • Confounders: two small house-convention episodes, one model, a local episode-suite closure, and a 120-second session bound. This is curriculum evidence, not a broad skill benchmark.
    META_EVOLVE_LIVE_CLAUDE=1 uv run --extra claude \
  python examples/08_skill_evolution/main.py

    The model runs inside the evaluator, so the evaluator component identity names the model, episode names, and session bound. That prevents Run.compare from ranking two silently different model configurations. The examples/08_skill_evolution/README.md owns the live measurement and caveats; the call arithmetic is pinned by tests/test_skill_evolution_example.py.

    Failures are outcomes, not bad scores

    A score of 0.0 means the evaluator ran successfully and measured zero. These facts carry no score and must never be converted to zero:

    • provider or infrastructure failure;
    • timeout or turn-limit failure;
    • invalid candidate or missing derivation;
    • evaluator or grader failure;
    • an episode that produced no candidate.

    They are typed trial or evaluation outcomes. If every candidate has one, there is no best score. Report the failure kinds and details. In skill evolution, an unfinished episode becomes EvaluatorFailure; it does not lower the candidate's episode average. In the A/B report, typed failures stay named in the attempt sequence rather than disappearing or becoming 0.0.

    Capability honesty: Codex has no finite wall deadline

    The M6 measurement record concludes RuntimeCapabilities.interruptible=False for the pinned Codex SDK surface. The shipped Codex adapter preserves that fact: any finite Budget.wall_seconds is rejected during validate_run, before provider traffic or run events, because native interruption does not verify descendant cleanup. The repository exercise therefore declares evaluation and trial limits but no finite wall limit.

    Claude has measured interruption support and an adapter timeout. A finite core wall budget is accepted only when the Claude timeout fits inside it. This is a narrow capability difference, not evidence that the providers are otherwise equivalent.

    Optional advanced work: prompt optimization

    The prompt-optimization example is deliberately outside the 12-call pass. Its maximum is 14 Claude sessions, and the cases shown to the rewriter are not a second unseen validation split. Use it only as a separate, more expensive study of eval-driven rewriting and overfitting risk.

    No live example or credentialed provider test runs in CI. The deterministic tests exercise the same seams with fake transports; live runs remain explicit operator actions.
