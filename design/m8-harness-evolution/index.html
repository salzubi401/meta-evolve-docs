    M8 harness-evolution design brief

    Status: Design—not shipped. This brief is subordinate to the shipped API, architecture, and M8 acceptance gate.

    Design one bounded experiment: start from a worker harness containing a planner prompt and context policy; let an outer proposer change only those surfaces; score each candidate on fresh held-out repository tasks under equal budgets; compare it with the unchanged harness; leave promotion external.

    The future demonstration is reserved for examples/20_harness_evolution/. No HarnessArtifact, MutationSurface, episode-suite, or filesystem-egress implementation belongs in a documentation PR.

    Map onto current seams

    M8 concept Current seam
    HarnessArtifact Artifact codecs, registries, component identity, and lineage
    MutationSurface Proposal validation, policy violations, and workspace capture
    Held-out evaluation Evaluators launching bounded fresh inner runs
    Harness comparison Run summaries, usage, failures, and comparison validity
    External promotion A governance decision after search selection

    Required decisions

    Artifact and identity

    Define the exact versioned manifest fields, component references, interfaces, content digest, occurrence identity, parent lineage, and behavior-affecting configuration. Equal content in two causal positions remains two occurrences.

    Mutation authority

    Name the planner-prompt and context-policy fields a candidate may change. A validator must reject changes to tasks, evaluator, hidden data, secrets, permissions, budgets, audit history, or promotion without creating a successor.

    Held-out evaluation

    Define a portable episode-suite representation, fresh inner runs, nested seeds, budgets, environments, cache keys, evidence, uncertainty, and typed failure aggregation. A local closure prototype must state that it is local-only.

    Comparison and promotion

    Baseline and candidate declarations must agree on the suite, model, evaluator, environment, and effective budget before ranking. Quality, cost, robustness, and failure views feed a separately governed promotion record; best() never deploys anything.

    Replay and extensions

    Name every new durable fact and demonstrate reconstruction without rerunning a committed episode. A second mutation-surface implementation must pass the same conformance suite without a coordinator branch.

    Current blockers

    1. Custom codecs are local-only. They carry no verified resume manifest.
    2. No portable episode-suite representation exists. Current nested suites close over local values.
    3. Conformance coverage remains incomplete. Published suites do not cover every needed seam.
    4. Hidden configuration requires explicit component identity. Model, suite, timeout, and environment affect behavior.

    Acceptance evidence

    • Valid prompt and context-policy mutations use one ordinary coordinator path.
    • Authority violations are typed rejections with no successor artifact.
    • Composite identity, lineage, component provenance, nested usage, and failures replay.
    • Held-out inner runs are fresh and comparison fails closed on mismatched controls.
    • Resume performs no committed episode twice.
    • Promotion remains an explicit external outcome.

    Final review must make candidate authority, distinct causal identity, parent lineage, effective budget, every typed failure, replay, comparison validity, and promotion ownership explicit.
