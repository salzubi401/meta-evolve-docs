    M8 harness-evolution design brief

    Status: Design—not shipped. This retained decision brief records the design that preceded M8 implementation. Current executable semantics live in the shipped programming model and architecture; official-SDK validation remains the M8.6 blocking gate.

    Design one bounded experiment: start from a worker harness containing a planner prompt and context policy; let an outer proposer change only those surfaces; score each candidate on fresh held-out repository tasks under equal budgets; compare it with the unchanged harness; leave promotion external.

    The deterministic demonstration is examples/20_harness_evolution/.

    Its execution boundary is decision-complete: the example accepts a user-owned proposer callable, CI drives it with a deterministic fixture-backed SDK client, and an opt-in maintainer driver may invoke a real SDK through the same callable shape. See the user-owned SDK boundary. The first authorized live run is captured once and sanitized without dropping regressions, ties, or failures. Evaluation, equal budgets, mutation authority, and promotion remain outside the wrapper.

    Map onto current seams

    M8 concept Current seam
    HarnessArtifact Artifact codecs, registries, component identity, and lineage
    MutationSurface Proposal validation, policy violations, and workspace capture
    Held-out evaluation Evaluators launching bounded fresh inner runs
    Harness comparison Run summaries, usage, failures, and comparison validity
    External promotion A governance decision after search selection
    SDK execution A user-owned callable returning a candidate or ProposalResult

    Locked executable decisions

    • Search evaluates development episodes. Held-out episodes evaluate only the unchanged baseline and selected candidate, each with Greedy(max_trials=0).
    • Candidate encoding is followed by generic core-side successor validation before artifact commit. MutationSurface.apply() is convenience only.
    • The parent declares mutable surfaces. Successors cannot change parameter names/types, component references, interfaces, or non-surface state.
    • Planner text and context policy are independent implementations governed by one published conformance suite.
    • Evaluator identity includes exact suite content, worker/model declaration, budgets, timeouts, environment, and scoring/aggregation rule.
    • Resume guarantees begin at a committed outer evaluation. Uncommitted inner work may repeat.
    • One held-out fixture demonstrates the boundary; it is not statistically strong promotion evidence.

    Implemented artifact and identity

    The built-in artifact is agent-harness / harness-manifest-v1, with exactly one TextParam planner and one PolicyParam context policy. Existing artifact occurrence identity, content digest, lineage, and component references apply.

    Mutation authority

    Only text and policy configuration change. The codec returns InvalidOutput for malformed/no-op transitions and PolicyViolation for authority expansion; the proposal, evidence, and typed failure commit without a successor artifact.

    Held-out evaluation

    Portable episode values and fresh inner runs are implemented. Hidden tests and process controls remain evaluator-only; captured attempts, diagnostics, diffs, failures, and counts become outer evidence.

    Comparison and promotion

    compare_harnesses enforces the full equality gate and reports quality, actual usage, failures, verdict, and eligibility. best() never deploys anything.

    Replay and extensions

    Outer episode capture is ordinary durable evidence. Fault injection proves a committed outer evaluation is not repeated. Both built-in surfaces pass the same published suite without a coordinator branch.

    Remaining blocker

    The first authorized official-SDK result is committed without dropping its failures or tie: strict output-schema validation rejected both proposal calls, so no native mutation reached decoding or successor validation. M8 remains Experimental/live-only until a future separately authorized capture exercises that boundary; the failed result remains part of the record.

    Acceptance evidence

    • Valid prompt and context-policy mutations use one ordinary coordinator path.
    • Authority violations are typed rejections with no successor artifact.
    • Composite identity, lineage, component provenance, nested usage, and failures replay.
    • Held-out inner runs are fresh and comparison fails closed on mismatched controls.
    • Resume performs no committed episode twice.
    • Promotion remains an explicit external outcome.

    Final review must make candidate authority, distinct causal identity, parent lineage (the parent lineage invariant), effective budget, every typed failure, replay, comparison validity, and promotion ownership explicit.
