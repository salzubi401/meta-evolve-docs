    User-owned SDK boundary

    Status: Design—not shipped. This retained decision record preceded the deterministic M8 flagship and opt-in driver; the authorized live capture is still pending. The callable boundary itself and the hard-removal migration it gates are shipped; the migration guide is their canonical record. This page adds no agent runtime, provider adapter, or M8 domain type.

    Decision

    Meta-Evolve accepts an ordinary callable or an object with a structural propose() method. The user invokes and configures any model SDK inside that boundary. The SDK owns authentication, sessions, tools, permissions, structured decoding, and provider telemetry. Meta-Evolve owns candidate validation, independent evaluation, budgets, durable records, lineage, experience auditing, and promotion authority.

    There is no provider ABC and no generic agent runtime. A direct candidate return remains the smallest path; ProposalResult is the typed path when a wrapper has usage, evidence, metadata, or derivation to report.

    SDK wrapper output Meta-Evolve destination
    Decoded artifact value ProposalResult.candidate
    Total tokens and elapsed time Usage.tokens and Usage.wall_seconds
    Raw response, monetary cost, model, granular tokens, provider telemetry EvidenceDraft or metadata
    Audited observations actually used derived_from

    Trial and evaluation counts are coordinator-owned. A wrapper that reports either count is normalized to typed InvalidOutput, and completion overwrites both counts independently as defense in depth. Monetary cost and granular token categories remain provider evidence, not shared budget fields.

    Ordinary SDK exceptions become ProposerFailure. Framework failures that state a fact about durable state, accounting, or run capability escape unchanged: EventStreamConflict, DurableCorruption, InvalidSearchHistory, ExperienceStoreUnavailable, ExecutionAccountingUnknown, and CapabilityError.

    Audited agent pull

    A user wrapper may register an SDK custom tool whose handler delegates to the scoped context.experience reader. The handler returns only the authorized observation and retains the observation references that the SDK actually used; the wrapper returns those references in ProposalResult.derived_from.

    SDK tool call
  -> user handler
  -> context.experience.search/open/ancestors/siblings/compare
  -> audited, bounded observation
  -> SDK
  -> ProposalResult(derived_from=used_references)

    The callback can be in-process or forwarded through a user-owned RPC bridge. Meta-Evolve adds no process or tool protocol for that bridge. Access denial, exhaustion, audit-store failure, and unknown accounting keep their existing semantics because the handler delegates to the scoped reader rather than copying or bypassing it. SDKs without custom-tool support may receive pushed context.bundle content, but that is not agent-directed pull.

    M8 flagship execution

    The examples/20_harness_evolution/ demonstration accepts a user-owned proposer callable. CI uses a deterministic fixture-backed SDK client. The opt-in maintainer driver invokes a real SDK through the same callable boundary, without a package dependency or a shipped provider example.

    The first authorized live M8 run must be captured once, sanitized, and retained honestly. The capture must preserve ties, regressions, typed failures, and unsuccessful attempts rather than rewriting them into a success narrative. It must identify the wrapper declaration and the controls that affect behavior.

    The wrapper may propose only manifest-declared planner and context-policy changes. External evaluators run fresh held-out episodes under equal effective budgets. Candidate code cannot change evaluation, grants, hidden inputs, budgets, promotion rules, or mutation authority. best() selects a recorded result; promotion remains a separate governed action.

    The provider removal was gated on this boundary and the audited experience bridge being complete, and shipped in the same change as both. No The M8 types are implemented elsewhere; this decision still adds no provider ABC, agent runtime, or core SDK adapter.

    Removal and evidence policy

    The pre-1.0 migration is a hard removal: first-party Claude and Codex imports, extras, adapters, fixtures, and live tests receive no compatibility shim. Historical experiments and milestone records remain accessible and are labeled superseded. Their original claims are evidence of what was tested at the time; they are not current package instructions or shipped fixtures.

    The repository boundary applies to current src/, examples, and shipped guides. Provider names remain legitimate in historical experiments, milestone records, design decisions, and migration material.
