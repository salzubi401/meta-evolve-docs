    Meta-Evolve Programming Model

    Status

    This document is the canonical specification for Meta-Evolve's target user-facing and policy-authoring API. Milestone 7 is complete: the kernel is domain-agnostic across the built-in artifact domains and repository proposers, with explicit extension and conformance contracts; Milestone 8 is next. Milestone 6 is complete: independent Claude and Codex proposers enter through the same structural proposer seam as local callables, with provider-native pull experience and no provider framework in core. Milestone 5 is complete: immutable UTF-8 source trees, exact-file patch proposals, synchronous replaceable workspaces, bounded POSIX development subprocesses, and external command evaluation compose through the existing callable path without a coordinator special case. Milestone 4 ships the local and durable-local execution profiles, durable storage, verified component manifests, and resume: a durable-local run can reopen after process failure and reach the uninterrupted logical result, including runs that declare context or experience. Durable record serialization remains schema version 3 (CURRENT_SCHEMA_VERSION); the SQLite store format is independently versioned and migrates version 1 to version 2 to add per-event content integrity. The distributed profile remains target API. The architecture document owns domain semantics and invariants; the milestone roadmap owns implementation order.

    The smallest useful mental model

    A user supplies five things:

    Task       what counts as success and what is allowed
Seed       the initial immutable artifact
Proposer   how candidates are produced; an AI agent is one implementation
Evaluator  how candidates are measured; normally part of the Task
Search     where the next unit of compute goes

    The minimal local API is:

    def mutate(parent, context):
    return parent + 1


def evaluate(candidate):
    return {"score": -abs(candidate - 10)}


task = meta.Task(evaluator=evaluate)

run = meta.run(
    task=task,
    seed=0,
    proposer=mutate,
    search=meta.Greedy(max_trials=50),
)

print(run.best())
print(run.lineage())

    The same story applies to immutable source:

    source = meta.load_source_tree("candidate/")


def repair(tree, context):
    return meta.TextPatch(
        path="clamp.py",
        expected=tree["clamp.py"],
        replacement=FIXED_CLAMP,
    )


task = meta.Task(evaluator=evaluate_source, artifact=meta.SourceTree)
run = meta.run(
    task=task,
    seed=source,
    proposer=meta.PatchProposer(repair),
    search=meta.Greedy(max_trials=1),
)

    artifact= accepts any registered artifact type that declares string KIND and REPRESENTATION attributes — meta.SourceTree and meta.Text are the shipped examples. The same codec that encodes the seed also encodes every proposed candidate: a codec rejects a candidate it cannot represent by raising TypeError or ValueError, and such a rejection fails only that trial as a typed InvalidOutput, never the run. Any other exception from a codec is a codec bug rather than a rejection, and propagates. Task(artifact=meta.SourceTree) expands to the canonical durable kind and utf8-tree-v1 representation. PatchProposer materializes a fresh private directory, applies one exact replacement, captures a new immutable tree, and always disposes the workspace before commitment. PatchResult is the rich form when the patcher also reports evidence, usage, metadata, a typed failure, or observed-experience derivation.

    Source patchers and command evaluators are local components. Durable storage preserves their artifacts, evidence, and lineage for later Run queries, but does not make their live callbacks or providers reconstructible: meta.resume() fails with CapabilityError for such a local run. Milestone 6 shipped native SDK proposers as local-only components; portable reconstruction of patch, command, and native SDK proposer components remains later work.

    External grading is part of the same small task story:

    task = meta.Task(
    evaluator=meta.CommandEvaluator(
        command=meta.ProcessSpec(
            argv=(sys.executable, str(RUN_GRADER), str(GRADER)),
            environment={"PYTHONDONTWRITEBYTECODE": "1"},
        ),
        environment=meta.EvaluationEnvironment(
            name="python-clamp-tests",
            version="1",
        ),
    ),
    artifact=meta.SourceTree,
)

    CommandEvaluator, EvaluationEnvironment, and ProcessSpec are root vocabulary. ProcessResult, the provider protocols, and concrete development providers remain at the adapter boundary. A command evaluator is a live local callable component, so its history is durable but it is not cold-resumable.

    Each evaluation materializes the candidate into a fresh workspace, invokes the exact ProcessSpec, and disposes the workspace on every outcome. Exit 0 produces the passing score, exit 1 the failing score, and every other exit (including signal termination) an EvaluatorFailure. Timeout, resource, policy, and infrastructure failures remain their exact non-rankable M5.2 types. Cleanup failure overrides apparent completion because the evaluator cannot honestly report success while an owned workspace may remain.

    The evaluator records immutable evaluation-environment evidence and, when a process result exists, bounded process-result evidence containing its exit code, stdout, and stderr. It does not expose argv as candidate-visible evidence. The component version is 1+<sha256> over the complete command, environment identity, metric, scores, adapter version, and exit-protocol version, so those semantic changes alter task and run identity.

    The fixed protocol is deliberately small and trusted: a command that returns 0 after hiding its own grader failure can misclassify that failure. The canonical grader counts everything the candidate causes — wrong answers or candidate code that fails to load or run — as an ordinary exit 1 failure. The canonical runner script (run_grader.py in the example) maps grader-internal faults (a missing or crashing grader, malformed grader results) to exit 2, so a broken grader surfaces as an EvaluatorFailure instead of ranking every candidate as failing. Thus a completed exit 1 is rankable task performance with a failing score; EvaluatorFailure and typed timeout, resource, policy, or infrastructure failures carry no metric and are not rankable.

    The underlying immutable process fields and defaults are:

    ProcessSpec(
    *,
    argv: tuple[str, ...],
    cwd: str = ".",
    environment: FrozenMap | Mapping[str, str] = FrozenMap(),
    timeout_seconds: float = 30.0,
    stdout_limit: int = 1_048_576,
    stderr_limit: int = 1_048_576,
)

ProcessResult(
    *,
    exit_code: int | None,
    stdout: str,
    stderr: str,
    usage: Usage,
    failure: TimeoutFailure | ResourceExhausted | PolicyViolation
             | InfrastructureFailure | None,
)

    Construction validates declaration integrity: a nonempty string-argument tuple, string cwd and environment entries, a positive finite timeout, and nonnegative byte limits. Provider execution decides authority. The development adapter requires an absolute executable and normalized workspace-relative cwd, rejects workspace escape and malformed environment declarations, and passes only the declared environment.

    An exit code, including a nonzero one, is ordinary process completion. A timeout, per-stream raw-byte overflow, policy rejection, or infrastructure fault instead returns the corresponding typed failure and no exit code. Overflow terminates the process group immediately rather than letting the command continue with truncated reporting. Retained byte prefixes are bounded independently and decoded as UTF-8 with replacement. Usage records elapsed monotonic wall time; evaluation, trial, and token counts remain zero at the process port. CommandEvaluator attributes that wall time to evaluator usage, while the coordinator remains authoritative for evaluation counting. Source digests, scores, exit codes, failure types, evidence kinds, and lineage are deterministic for the canonical example. Measured wall time is an observation of one execution and is not promised deterministic.

    proposer is required because there is no meaningful universal mutation for an arbitrary artifact. search, context, and storage have simple local defaults. A composite strategy may itself implement the same proposer protocol without changing the run contract.

    The run-level context is the default inserted into trial decisions. A custom search program may choose another registered context policy for a particular trial, but it cannot exceed the run's experience grant or context budget.

    The same API should optimize integers, text, code trees, skill sets, harnesses, and search policies. Domain-specific behavior belongs in artifact codecs, proposers, evaluators, and policies—not in meta.run or the coordinator.

    Evidence from the pre-milestone spike

    The disposable API spike exercised this surface with deterministic integers and with a real gpt-5.4-mini Codex SDK prompt-optimization run. The observed use is recorded in experiments/00_api_spike/real_model_findings.md. It established these constraints on the target model:

    • The seed is evaluated as the baseline and consumes one evaluation. Search preset trial limits count successor proposal attempts, while evaluation budgets count actual evaluator calls.
    • Passing decoded values to plain proposer and evaluator callables worked for both integer and text artifacts. A printable ArtifactView with a .value payload was useful without exposing coordinator vocabulary.
    • Provider-backed callables produce evidence beyond their artifact or metrics: trace identifiers, outputs, duration, usage, and errors. Durable adapters must commit that evidence to trial outcome and evaluation records rather than forcing simple user callables to manage those records themselves.
    • Evaluation count alone is not a complete model-spend budget. Proposer and evaluator usage both consume task or run resources and must roll up into explicit usage budgets.
    • A root random_seed makes local decisions reproducible; it does not make an external model provider deterministic. Exact provider observations must be recorded for inspection and replay.
    • The minimal RNG-and-step proposer context was sufficient for a one-step experiment but did not expose prior evaluation feedback. The spike did not provide evidence that SearchState, TrialSpec, or composable policy protocols belong on the simple callable path; policy-author primitives remain a Milestone 1 decision.

    Canonical public surface

    The target public entry point is:

    def run(
    *,
    task: Task,
    seed: ArtifactLike,
    proposer: ProposerLike,
    search: SearchProgram | None = None,
    context: ContextPolicy | None = None,
    experience: ExperienceAccess | None = None,
    storage: Storage | None = None,
    budget: Budget | None = None,
    mode: ExecutionMode = "local",
    registry: Registry | None = None,
    random_seed: int = 0,
) -> Run: ...

    Defaults normalize to greedy search, no prior experience, in-memory storage, the task's declared budget, and local execution. A run-level budget may narrow but never widen the task budget.

    Two parameters are easy to confuse and are deliberately distinct: seed is the initial artifact the run improves, while random_seed is the root of the deterministic randomness described in Randomness and replay. In the integer example both happen to be integers; they never interact.

    meta.run validates the requested mode against the supplied components at call time and fails fast: supplying a closure with mode="durable-local" or mode="distributed" is an explicit capability error before any trial executes, never a silent downgrade. This validation happens before any event is written — a rejected mode="durable-local" call leaves no trace in storage.

    CapabilityError is reserved abort control flow. It means this run cannot proceed — a fact about configuration or the machine, identical for every candidate. It is not a per-candidate outcome and must not be raised conditionally on a candidate. It escapes proposer and evaluator boundaries unwrapped instead of being converted into a typed ProposerFailure or EvaluatorFailure; a run that meets one aborts rather than recording a failure. Because meta.CapabilityError is exported, this binds user code as well: a proposer or evaluator that drives a provider session or an inner run one level down lets a refused preflight through unchanged, and one that raises CapabilityError for some candidates and not others is misusing it — the run aborts on the first, by contract rather than by accident. Everything a candidate can genuinely cause — invalid output, a timeout, a policy violation, an inner run with nothing to rank — remains a typed failure of that trial and is never a CapabilityError.

    registry is an explicit, non-ambient map from (role, name, version) component identities to live callables and policy factories (Registry, meta_evolve.registry). Registration returns the typed ComponentRef that the task or run uses, so callers do not re-spell identities:

    registry = Registry()
proposer = registry.register_proposer(
    "example:propose", "1", propose,
    deterministic=True, retry_safe=True,
)
evaluator = registry.register_evaluator(
    "example:evaluate", "1", evaluate,
    deterministic=True, retry_safe=True,
    configuration={"target": TARGET},
)
task = meta.Task(evaluator=evaluator, budget=meta.Budget(evaluations=8))
result = meta.run(
    task=task, seed=0, proposer=proposer,
    search=meta.Greedy(max_trials=8),
    storage=meta.Storage.durable(".meta-evolve"),
    mode="durable-local", registry=registry,
)

    register_artifact_type(codec) registers a (kind, representation) artifact codec together with its declared interfaces, extending the same registry beyond proposers, evaluators, and search and context policies. The built-in (kind, representation) keys — python-value/canonical-json, source-tree/utf8-tree-v1, text/utf8-text-v1, and skill-set/utf8-tree-v1 — are non-overridable: registering any codec under one of them is rejected, the built-in object included, since changing the decode for an old key would change the meaning of every artifact already committed under it. A new representation of a built-in kind is a different key and registers normally. The last two keys share a representation and differ only by kind: the same portable tree bytes read under a different schema, which is what the kind/representation split is for. kind, representation, and each declared interface name must be non-empty strings without outer whitespace; interfaces=() is valid. Registration rejects invalid declarations rather than trimming fields that participate in durable identity and codec resolution. A registered codec is a live object rather than a source function and so carries no verifiable manifest: custom artifact types remain local-mode only in Milestone 7, and mode="durable-local" fails closed with CapabilityError for any task whose (kind, representation) is not one of the four built-in keys — a new representation of a built-in kind is gated too.

    meta.SkillSet is a mapping from skills/<name>.md to UTF-8 text: a meta.SourceTree with one added layout rule and no others. What a skill says belongs to whoever reads it, so an empty skill is a legal candidate and is scored like any other. Its codec declares the interface skill-documents/v1, readable through Registry.artifact_interfaces("skill-set", "utf8-tree-v1"). The native agent proposers (Claude, Codex) accept only Task(artifact=SourceTree) and reject a skill-set task with CapabilityError; a skill set is evolved by an outer proposer that rewrites the skills, with agents running underneath as inner proposers on ordinary source-tree tasks.

    mode="durable-local" requires durable storage and registered proposer/evaluator references; local closures fail before any event is written. A successful run records a verified ComponentManifest for each executable component. A component digest covers the exact registered source plus each explicitly declared callable or module in dependencies=. Behavior-affecting values that are not source—such as an evaluator target—belong in configuration= and are hashed separately. This avoids both fail-open imported helpers and invalidation from unrelated code in the defining module. Search and context policy manifests cover their factory and resolved built-in implementation. The deterministic and retry_safe flags remain declarations, not runtime proofs. local runs retain LEGACY_LOCAL_CAPABILITIES and are not restart-resumable.

    An interrupted durable-local run is resumed with:

    def resume(run_id: RunId, *, storage: Storage, registry: Registry) -> Run: ...

    resume replays the committed stream, reconstructs the run's components from the recorded RunCapabilities, and re-enters the same decide/execute loop run uses so the resumed run reaches the identical best() value and final event stream. Comparing a resumed run's freshly resolved manifests against the ones recorded on its RunStarted (verify_manifests, keyed by (role, name, version) and independent of insertion order) gates execution on an unchanged, honestly-identified component set; this is shipped as of Milestone 4.4. Milestone 4.5 extends the same round-trip to context and experience: a run that declared a context policy has it rebuilt from the registry (resolve_context_policy over the recorded ContextSpec, gated by require_resumable like the proposer, evaluator, and search policy), and a run that declared experience has its ExperienceSpec rebuilt directly from the recorded ExperienceAccessDeclared. Only genuinely new post-crash trials re-select context; a trial that already committed its context bundle reuses the committed bundle on replay. A run whose context policy is no longer registered, or whose components are re-declared non-deterministic or non-retry-safe, fails closed with a CapabilityError rather than resuming onto a divergent path.

    Reopening a stored run needs its id, so storage answers which runs it holds:

    def runs(self) -> tuple[RunId, ...]: ...   # method on Storage

    Storage.runs() is read-only and returns identities, not Run objects: opening a run validates and replays its whole stream, and per-run detail is already Run.summary()'s job, so a listing returns exactly what Run(run_id, storage), resume, and compare need. The order is lexicographic by id and identical for the in-memory and durable backends; run ids are content-derived, so it is not chronological. Only runs with at least one committed event appear.

    Enumeration is an optional store capability, ports.RunIndex, rather than a required EventStore method — append and read are both run-scoped, so a store can address a stream by id without holding a directory of streams. Both bundled event stores implement it. A paired store that does not is refused with CapabilityError, never reported as an empty store.

    A task accepts an evaluator directly; registry references are an advanced durable form of the same field:

    Task(
    evaluator=evaluate,                    # callable in local mode
    objectives=[meta.Maximize("score")],
    budget=meta.Budget(evaluations=50),
)

Task(
    evaluator=meta.EvaluatorRef("grader@3"),  # portable durable form
    objectives=[meta.Maximize("score")],
    budget=meta.Budget(evaluations=50),
)

    A simple proposer is a callable. The richer protocol can return hypotheses, predictions, and derivation references:

    class Proposer(Protocol):
    def propose(
        self,
        parent: ArtifactView,
        context: ProposerContext,
    ) -> CandidateLike | ProposalResult: ...

    ProposerContext(*, rng, step, objectives, bundle, experience=None) is the canonical execution context. It is frozen, slotted, and keyword-only. The bootstrap has no user proposer. Every successor receives the Task's ordered objective tuple, the exact committed bundle, and its named random stream. When PullAccess is declared, it also receives a scoped ExperienceReader; otherwise experience remains None. It exposes no Task, evaluator, promotion decision, or hidden state. ProposalContext remains an internal compatibility alias only; neither name is exported from the package root.

    An SDK-backed AI agent, deterministic mutator, human workflow, or composite harness can be a non-callable object implementing only propose(parent, context). A full runner implementing execute(parents, context) and declaring a proposer ComponentRef takes precedence when an object implements both forms. Ordinary callables continue through the decoded value adapter.

    Before any proposal, workspace activity, or genesis write, the application invokes one optional proposer hook:

    def validate_run(
    *,
    artifact_kind: str,
    artifact_representation: str,
    objectives: tuple[Objective, ...],
    budget: Budget,
    experience: ExperienceSpec | None,
) -> None: ...

    This is a pure declaration check. It receives the effective run budget and the normalized experience declaration, not a Task. The same recorded values are used when a registered proposer is reconstructed by resume. A proposer-raised CapabilityError is preserved; other validator exceptions are wrapped without copying their text and remain available as the cause.

    Structural proposers retain the exact passed object in a local proposer ComponentRef; bound propose and validate_run methods are stored separately and are never identity-compared. A configured adapter owns a canonical, secret-safe _identity_payload and declares version="1+<configuration digest>", covering every safe field that changes behavior. Core propagates and compares that declaration without inspecting arbitrary adapter state. Such local proposers are manifest-free, non-resumable, and rejected by durable-local.

    R1 adds no shared provider runtime, assignment/result transfer objects, permission model, or provider option vocabulary. R2 exposes its closed adapter only from the provider module:

    from meta_evolve.claude import Claude

proposer = Claude(
    model="claude-sonnet-5",
    instructions="Improve the repository.",
    output_schema=None,
    timeout_seconds=300.0,
    max_turns=4,
    pull_max_turns=12,
)

    Claude accepts SourceTree tasks, exact pushed context, and PullAccess. Its ordinary native profile is adapter-owned: Read, Edit, and Write, acceptEdits, the claude_code preset, no settings sources or MCP servers, and a fresh session in a private workspace. Native schema output also exposes the SDK-owned StructuredOutput tool. The turn ceiling is the one part of the profile a caller declares — four ordinary and 12 pull by default, both settable; see max_turns below. Pull runs add one in-process MCP server exposing the five bounded reads plus derivation declaration. Typed init and MCP status must report the exact conditional inventory before mutation records are accepted; provider-chosen tool order is not a mismatch, and the raw ordered list stays recorded as evidence. Captured files are the candidate; independently revalidated native structured output is evidence only. The optional meta-evolve[claude] extra pins the SDK and supplies adapter-only jsonschema validation while core dependencies stay empty.

    The configured timeout is a native per-proposal deadline. An unbounded core wall budget is accepted; a finite wall budget is accepted only when timeout_seconds <= budget.wall_seconds. Core wall accounting remains cumulative and authoritative after completion. At the deadline the adapter interrupts the session and waits a bounded grace for terminal accounting; if the session does not reach a terminal result within that grace, the stream is abandoned and the run aborts rather than reporting invented usage. Finite token budgets are unsupported because exact usage is known only after a turn. The root package export list is unchanged.

    max_turns and pull_max_turns are the two turn ceilings that were the fixed four and twelve above. They keep those defaults; which one applies to a given session is chosen by whether the run declares experience. A session that reaches its ceiling on an error terminal is a ProposerFailure with reason="turn_limit" — a typed failure carrying the limit and the turns taken, never a low score — so a task that needs one more turn than the adapter allows reports the harness's budget rather than the candidate's quality. A successful terminal at the ceiling stays a success. The limit that classifies is the same value that was sent to the provider, not a re-derived one.

    Both parameters are part of the adapter's _identity_payload, so component.version depends on them and Run.compare will refuse two runs whose proposers declare different turn ceilings. That is correct: the turn budget is part of what a run measured. What Run.compare cannot see is a turn asymmetry inside one instance — an instance carries both limits, the experience declaration picks between them, and differing on that declaration is permitted by design because it is an experience A/B's independent variable. An experiment that varies experience while holding provider budget fixed must therefore declare the two limits equal itself, as examples/12_experience_ab does.

    Each limit must be a positive int; bool is rejected. Clamping a declared limit upward for pull sessions — max(requested, 12) — was rejected: silently running under a number the caller did not choose is the same defect as the constant it replaced.

    R3 exposes its independent closed adapter only from its provider module:

    from meta_evolve.codex import Codex

proposer = Codex(
    model="gpt-5.4-mini",
    instructions="Improve the repository.",
    output_schema=None,
)

    Codex accepts SourceTree tasks, arbitrary ordered objectives, exact pushed context, and PullAccess. It rejects every finite token or wall budget. It has no adapter timeout; an unresponsive native turn can therefore block meta.run indefinitely. The constructor exposes only model, instructions, optional output_schema, and an optional WorkspaceProvider. The root package export list remains unchanged.

    The fixed native profile uses a disposable private CODEX_HOME, fixed client metadata, one ephemeral thread at the exact workspace cwd, deny-all approvals, workspace-write sandboxing, and one medium-effort turn with optional native structured output. Only a regular file-backed auth.json is copied byte-for-byte into the private home, with mode 0600; the adapter never parses or records its contents. An exact-cwd untrusted project entry keeps project .codex configuration inactive. Ambient config, MCP, plugins, hooks, and skills are not copied, while exact parent AGENTS.md content may participate through native discovery. Pull runs add an authenticated in-process loopback HTTP MCP server through literal private-home TOML. Thread-level deny_all remains active; per-server/per-tool configuration approves exactly search, open, ancestors, siblings, compare, and declare_derivation. The five reader tools are read-only; declaration is non-destructive but state-changing.

    Typed thread-start readback is verified before mutation records are accepted. Workspace capture is the sole candidate; provider prose is discarded and decoded structured output is independently revalidated as evidence only. Native shell, discovery, and possible provider-owned tools are irreducible, so the adapter claims no exact tool ceiling. Workspace-write is a configured mechanism, not a network or hostile-process containment guarantee: it leaves /tmp and $TMPDIR writable, and the native session inherits the host process environment because the pinned SDK provides no way to clear it. Run Codex from a process whose environment you are willing to expose to the native shell.

    Codex usage is input plus output tokens; cached input and reasoning output are inclusive qualified detail, while cache writes and monetary cost stay unknown. A completed failure can retain postconditions but never commits partial files. Cleanup failure overrides a reportable result while preserving known usage. Cancellation requests native interruption and drains/closes where possible, but descendant cleanup remains unconfirmed. If execution may have started and required usage is unavailable, ExecutionAccountingUnknown aborts the local run rather than fabricating zero usage or a resume claim.

    Both pull prompts use protocol v2. Pushed records receive sequential trial-local handles in bundle order; successful reads add newly observed references in the same canonical order used by the derivation ledger. Successful tool results include handles, kinds, logical steps, structured values, exact policy rendering, truncation, and cumulative usage. Expected denial and exhaustion are content-free errors, and exhaustion latches further reads while leaving the unaudited declaration available. Bindings reject malformed arguments and unknown handles before the reader. The final declaration must be a unique ordered subsequence of observed handles; the last valid declaration wins. Core resolves handles back to exact references and remains authoritative for grants, logical time, charging, auditing, evaluator separation, and derivation validation.

    Unexpected reader/store faults latch. Claude interrupts and drains before cleanup. Codex cannot claim reliable interruption; it drains for its bounded 60-second cleanup window, discards all workspace mutations, and aborts with the existing accounting rules. Both adapters remain manifest-free local components and are rejected by durable-local; deterministic replay remains available through registered callables, not native provider sessions.

    Claude and Codex sessions, tools, approvals, structured-output mechanisms, usage details, and interrupt behavior remain inside their independent thin adapters. Shared conformance covers only producer-neutral outcomes. No equivalence is claimed for models, quality, tokens, cost, compute, wall deadlines, native tools, environments, containment, or interruption behavior.

    ProposalResult.derived_from is an ordered tuple of typed ExperienceRef values. It declares which pushed or pulled observations actually informed the result; it is not an automatic union of everything the proposer saw. The declaration must be a unique subsequence of the trial's committed observation ledger. References remain strictly prior, same-run, and visible, so committed derivation edges are acyclic.

    Evaluators follow the same progressive interface:

    class Evaluator(Protocol):
    def evaluate(self, candidate: ArtifactView) -> EvaluationLike: ...

    A local evaluator may return a scalar or metric mapping. The adapter normalizes it into a typed Evaluation. Advanced evaluators receive the task and versioned environment and return measurements, uncertainty, evidence, usage, and a typed outcome. Evaluation always remains outside candidate authority.

    The initial Run query surface is:

    class Run:
    def __init__(
        self,
        run_id: RunId,
        storage: Storage,
        *,
        registry: Registry | None = None,
    ): ...
    def best(self, objective: str | None = None) -> ArtifactView: ...
    def best_trial(self, objective: str | None = None) -> TrialView: ...
    def trials(self) -> tuple[TrialView, ...]: ...
    def lineage(self, artifact: ArtifactRef | None = None) -> Lineage: ...
    def experience_usage(self) -> RunExperienceUsage: ...
    def summary(self) -> RunSummary: ...
    def compare(self, other: "Run") -> RunComparison: ...

    Run(run_id, storage) is the public read-only reopening path and resolves the built-in codec set. Pass registry=... when reopening a stored local run over a custom artifact domain. Reopening deliberately makes every artifact codec in that registry available for decoding, while the committed run projection still determines the one artifact kind each query reads. Supplying a registry grants no mutation, execution, resume, evaluation, budget, or promotion authority. A Run returned directly by run() or resume() retains the exact per-run codec index internally through a private reopening path.

    best() returns an ArtifactView: its .value is the codec-decoded payload, and printing it shows the value rather than an envelope of digests, so print(run.best()) in the integer example prints the winning integer. The full experimental record — proposal, evaluation, evidence, lineage references — is reached through best_trial() or lineage(). These are query helpers over committed records; they do not grant mutation or promotion authority.

    trials() answers the other question: not what came out of the run, but what happened in it. It returns one TrialView per committed attempt in commit order, starting with the seed trial, and TrialView.state separates the four ways an attempt can end — "evaluated" (scored), "evaluation_failed" (the candidate exists but the evaluator failed), "trial_failed" (no candidate was produced, so artifact is None), and "unevaluated" (the candidate exists but the remaining budget never authorized an evaluation, so it carries no metrics and no failure). Because losers and failures are the point, trials() is the one query that does not raise NoSuccessfulEvaluation; a run whose every evaluation failed still reports its attempts and their typed failure kinds. The word "trial" is already public vocabulary on the query surface — best_trial() returns a root-exported TrialView — which sits downstream of the simple callable path rather than on it.

    experience_usage() returns immutable channel-specific totals: committed selected-bundle ContextUsage and the last cumulative ExperienceUsage once per pull grant. Memory access remains outside task and run budgets.

    summary() returns a frozen, storage-independent RunSummary containing the run identity, policy declaration, primary score, evaluation count, total task usage, root random seed, the codec-decoded initial artifact value and its content digest, the codec-decoded values on the winning lineage, exact context and pull declarations, the same aggregate memory usage, and the roles whose recorded component identity is a name only. It raises NoSuccessfulEvaluation rather than turning evaluator failure into a score.

    compare() accepts only another Run. It requires exact equality of evaluator and proposer declarations, task artifact kind, primary objective metric, direction and threshold, task and effective run budgets, and the initial artifact's kind, representation, schema, and content digest. Different search policies, policy configurations, memory declarations, and root seeds are permitted. same_random_seed, same_context_declaration, and same_experience_declaration report those exact relationships. The primary objective direction chooses the winner. Exact score equality is a tie, and usage, cost, policy name, and completion order never break one. The comparison's winner is the exact left or right summary object, or None for a tie.

    Component equality is declaration-based. In local mode, callable identity is the existing module:qualname declaration; matching local declarations do not prove that closures or other live callables are behaviorally equivalent. Two closures from one factory over different captured state — different models, different thresholds — declare the same component, so compare() accepts them and names a winner. Local mode records no component manifests, so that difference is genuinely absent from the record rather than merely unread; the summary therefore reports it. RunSummary.name_only_components is the sorted tuple of roles ("evaluator", "proposer") whose recorded reference is a module-and-qualname name and nothing else.

    The field states a fact about the roles it lists and certifies nothing about the ones it omits. It does not assert that the other roles are behaviorally equivalent or source-stable: a local component may version itself with a configuration digest — CommandEvaluator digests its whole configuration — and is absent from the list because it is configured, not because it is verified. Only a ComponentManifest, which local mode does not record, represents a verified component identity. RunSummary and RunComparison are derived application views, not durable serialization types.

    ComponentRef.configured_local(role, adapter, name=…, version=…) is how a caller escapes the name-only default. It declares a local component whose version says what configured it, so a closure that captures a model id, a threshold, or a case list can record that rather than collapsing to its module and qualname; Claude, Codex and CommandEvaluator build their own references through it, each versioned by a digest over its whole configuration. Two things are derived rather than accepted: origin is always local, and the reference always retains the adapter it was given, because Task admits a callable's declared component only when it is a local evaluator reference holding that exact callable. The version must not be the run-local sentinel — a reference claiming to be configured while still reporting as name_only is exactly the state the report exists to expose — and passing it raises ValueError.

    Declaring it is what makes compare() able to refuse a differing configuration. Component equality is declaration-based, so two runs whose evaluator closures were configured differently compare cleanly for as long as neither says so; once they declare, the comparison raises RunsNotComparable("evaluator component") instead of ranking an uncontrolled pair. examples/17_model_migration does this with the model its case suite runs against.

    The executed milestone_2_tour.ipynb introduces the complete M2 path from public policy swapping and comparison to optional inspection of recorded decisions, explanations, archives, and replay.

    The simple path is also a progressive-disclosure commitment: a user on the callable path writes only Task, meta.run, a proposer function, an evaluator function, and preset search objects. Trial, TrialSpec, OperatorSpec, WorkItem, and event types are policy-author and kernel vocabulary that must never be required — or surfaced — by the simple path.

    Execution profiles

    One semantic kernel supports progressively stricter component requirements:

    Profile Accepted components Guarantees
    local Plain callables, closures, and live Python objects Fast iteration; portability and process-restart recovery may be unavailable.
    durable-local Versioned, serializable components and stable artifact codecs Crash recovery, replay, and local provenance.
    distributed Portable registered components, explicit environments, and remotely resolvable artifacts Cross-process scheduling and reproducible execution subject to declared infrastructure guarantees.

    A run records its actual capabilities. Supplying a closure must not silently produce a run advertised as portable or restart-resumable. Moving to a stricter profile changes admissible component representations, not trial, evaluation, authority, or search semantics.

    local and durable-local are shipped: durable-local's "versioned, serializable components" requirement is enforced by an explicit registry (above) rather than by artifact codec stability alone, since the local durable profile stops short of the distributed environment digest. Milestone 4.3 shipped durable-local run creation and recorded capabilities, Milestone 4.4 shipped resume, and Milestone 4.5 made durable-local runs that declare context or experience fully durable and resumable. distributed remains target API.

    The command line

    meta-evolve is five verbs over the surface above, each parsing its arguments, making one public call, and printing the result:

    Verb Call
    run <module> meta.run
    list Storage.runs()
    inspect <run-id> Run.summary() and Run.best()
    resume <run-id> --module <module> meta.resume
    compare <left> <right> Run.compare

    list is a deliberate widening of "run, inspect, resume, and compare": a store you cannot enumerate makes the other verbs unusable once the run ids have scrolled out of the terminal.

    An experiment module exposes exactly one factory returning meta.run keyword arguments — task, seed, proposer, and optionally search, context, experience, registry, random_seed:

    def experiment() -> dict:
    return {"task": ..., "seed": 0, "proposer": ..., "search": Greedy(max_trials=8)}

    It must have no import-time side effects: the command line imports it to call the factory, so a module that runs on import is a script, not an experiment module. The command line overlays only the infrastructure it owns, --storage <path> (required) and --mode local|durable-local (default local); a factory that returns storage, mode, or budget is a usage error rather than a silently ignored value. --module takes either a path ending in .py (whose directory is appended to sys.path, so an experiment module can import its siblings) or an importable dotted name; both give the module the same name, so recorded component identities do not depend on how a run was launched.

    The command line contains no capability logic. Mode semantics are the library's, unchanged: a local run in durable storage is listable and inspectable but not resumable, and resume reports the library's own CapabilityError rather than pre-empting it; durable-local requires the factory to supply registered components, which meta.run enforces. CLI inspection and comparison remain built-in-codec-only because those verbs accept no registry; stored custom-domain local runs are reopened through Python with Run(id, storage, registry=registry). Exit codes are 0 success, 1 domain failure, 2 usage error.

    Conformance suites for extension authors

    meta_evolve.conformance publishes two of the component contracts — artifact codecs and repository-editing proposers — as pytest suites, on the pandas ExtensionArray model: each suite is a class whose collaborators arrive as fixtures. Subclass it, name the subclass Test... so pytest collects it, and override the fixtures. The Recipe domain below is the one the add-a-domain tutorial builds.

    from meta_evolve.conformance import ArtifactCodecTests

class TestRecipeCodec(ArtifactCodecTests):
    @pytest.fixture
    def codec(self): return RecipeCodec()

    @pytest.fixture
    def values(self): return (Recipe(("preheat",)), Recipe(()))

    @pytest.fixture
    def rejected_values(self): return ("not a recipe", 7)
    Suite Covers
    ArtifactCodecTests payload and value round trips, repeated-call stability within one process, common file/socket I/O tripwires, TypeError/ValueError rejection, and identity-free payloads
    RepositoryProposerTests a repository-editing proposer through meta.run: the edit reaches storage and the evaluator, and the reported usage is exact
    PullRepositoryProposerTests the same under audited experience pull, including that a spent read budget refuses the read without failing the trial or losing the declared derivation

    Evaluators, search policies, context policies, workspaces, and sandboxes are not published. Search policies, workspaces, and sandboxes have unpublished internal contract suites under tests/; evaluators and context policies have concrete tests and no reusable suite. Publishing any of them is an additive change of the same shape as the three above.

    pytest is required to import this module and is the only place in meta_evolve that imports it — installing the library never pulls a test runner in, and nothing imports meta_evolve.conformance for you. Install it with pip install "meta-evolve[conformance]".

    The suites are not a second copy of the internal tests: tests/ subclasses these same classes for the four built-in codecs and for both providers, so the published kit and the kernel's own conformance cannot drift.

    These checks are evidence, not a complete proof of purity or reproducibility. Patching common file and socket entry points cannot intercept every possible side effect, and repeated calls establish only in-process stability. The built-in codecs additionally have a cross-process artifact-digest test under two fixed PYTHONHASHSEED values; third-party codecs need equivalent evidence appropriate to their own implementation and deployment boundary.

    One evaluated trial

    Milestone 1 record construction keeps the common path narrative while retaining raw frozen constructors for canonical deserialization:

    seed = Artifact(id=artifact_id, payload=initial_value)
proposer = ComponentRef.proposer("package:mutate", "1")
evaluator = ComponentRef.evaluator("package:score", "1")

outcome = TrialOutcome.succeeded(
    trial_id=trial_id,
    proposal_id=proposal_id,
    artifact_ids=(candidate_id,),
)
evaluation = Evaluation.succeeded(
    id=evaluation_id,
    trial_id=trial_id,
    artifact_id=candidate_id,
    evaluator=evaluator,
    metrics={"score": 1.0},
)

    Artifact computes its digest when omitted and validates an explicit digest supplied by a decoder. TrialOutcome.failed(...) and Evaluation.failed(...) construct the corresponding typed failure paths. Plain callable adapters use ComponentRef.local_proposer(...) and ComponentRef.local_evaluator(...).

    The atomic unit offered to a search algorithm is a TrialSpec:

    TrialSpec(
    task_id=task_id,
    parent_ids=(artifact_id,),
    proposer=proposer_ref,
    operator=OperatorSpec(kind="patch"),
    context_policy=context_policy_ref,
    budget=Budget(tokens=50_000, wall_seconds=900),
    random_seed=trial_seed,
)

    The coordinator accepts the specification as a first-class immutable Trial with its own identity. WorkItem is the scheduling envelope used to deliver that logical trial, while a lease or future WorkAttempt represents one retry. Retries do not create new trials.

    SearchDecision
  → TrialSpec
  → Trial
      → WorkItem
          → WorkAttempt or lease retry
      → TrialOutcome
          → Proposal
          → Artifact occurrence(s)
          → trace and usage
      → Evaluation(s)

ExperienceNode = a read projection over these records

    The coordinator interprets an ordinary trial through one fixed protocol:

    async def execute_trial(spec, run):
    context = context_policy.select(run.state, spec)
    context = coordinator.commit_context_bundle(context)
    trial = coordinator.start_trial(spec, context)

    work = coordinator.allocate(trial)
    execution = await proposer_runner.execute(work, context)
    coordinator.commit_proposal(trial, execution.proposal)
    artifact = await artifact_store.capture(execution.candidate)

    outcome = coordinator.complete_trial(trial, execution, artifact)
    evaluation = await evaluator.evaluate(run.task, artifact)
    coordinator.record_evaluation(outcome, evaluation)
    return TrialResult(outcome=outcome, evaluation=evaluation)

    proposer_runner adapts a local callable, deterministic mutator, workspace-backed SDK runtime, or another proposer without changing the protocol. TrialResult is a coordinator-facing evaluated view over the separately durable outcome and evaluation, not another experimental identity.

    Provider usage belongs to the execution that caused it. Tokens, wall time, and other resource measurements from both proposer execution and evaluation roll up against the applicable task, run, and trial budgets. An evaluation limit alone must never be reported as the total model-spend limit.

    Each operation validates budgets and authority and appends typed records and events. The snippet shows the logical sequence, not a database transaction or permission bypass. Any hypothesis or prediction used for calibration must be committed before the evaluator reveals the predicted evidence. Workflows requiring stronger preregistration may split proposing and applying into separate phases.

    For a merge or synthesis operation, parents may contain several artifacts. For replication, training, or scientific experimentation, the decision and result types can be extended without changing the meaning of an ordinary trial.

    OperatorPolicy and OperatorSpec occupy different levels. A policy chooses what operation to perform; the durable trial records the resulting typed specification. User-facing strings such as "patch" may be accepted as shorthand but are normalized before a trial is committed.

    The durable search contract

    The public algorithm contract should remain small:

    class SearchProgram(Protocol):
    archive: ArchivePolicy

    def next(self, state: SearchState) -> SearchDecision:
        """Return the next bounded action from committed state."""

    The current durable decision types are:

    SearchDecision = TrialSpec | ArchiveUpdate | Stop

    ArchiveUpdate is a policy declaration over an already completed evaluation. It records admission or rejection, an optional eviction, and the complete rank-ordered member IDs. It allocates no work and consumes no budget. Current membership is projected from these decisions rather than held in policy-local state.

    Later milestones may add typed decisions without expanding the method surface:

    SearchDecision = (
    TrialSpec
    | TrialBatch
    | ReplicationSpec
    | MigrationSpec
    | Stop
)

    The coordinator loop is therefore:

    while True:
    state = projections.search_state(run_id)
    decision = search.next(state)
    committed = coordinator.record(decision)

    if isinstance(decision, Stop):
        break

    if committed.trial is not None:
        await coordinator.execute(committed.trial)

    SearchProgram.next is re-entered from committed projected state at every logical step. Its Python stack and local variables are not durable state. Anything that affects a later decision must be derivable from events, artifacts, policy configuration, or versioned policy state recorded through the coordinator.

    This gives ordinary Python policies a simple interface while preserving replay and crash recovery.

    Each newly committed decision is immediately followed by a linked PolicyDecisionExplained fact. A policy may optionally return its rationale and the names of random streams it used; the runtime derives the actual seeds from SearchState.randomness. A description of a trial decision must name the "trial" stream, because that stream seeds the trial itself. Deterministic fallbacks explain trials, archive updates, and stops for policies implementing only next(state). These additive facts do not consume budget or advance logical decision numbering, and retained M1 streams without explanations remain readable.

    The M1 in-memory guarantee covers replay from retained events and decision reproduction. Durable storage, restarting a process, and resuming committed work are separate Milestone 4 guarantees, shipped through Milestone 4.5 for the durable-local profile (see resume, above).

    For the shipped Greedy, BestOfN, and Population presets, RunStarted retains a search declaration with the policy reference, the frozen declared configuration, and the authorized proposer reference. That is enough to reconstruct the bound policy against the recorded run budget and reproduce its historical TrialSpec, ArchiveUpdate, or Stop decisions. Custom programs remain identified by their policy reference and are responsible for declaring any configuration that affects next().

    Randomness and replay

    Randomness is explicit input, not hidden policy-instance state. A run has a root random_seed; each policy decision and trial receives a recorded deterministic substream derived from the root seed, policy version, logical decision identity, and a stable stream name.

    This guarantee ends at the boundary of a nondeterministic external component. For example, random_seed does not force a hosted model provider to reproduce a response. The run records the exact provider request, response, model identity, trace reference, and usage it observed; replay consumes those records rather than silently resampling and claiming equivalence.

    The following rules apply:

    • retries of one logical trial reuse its recorded trial seed;
    • worker identity and wall-clock completion order never affect random choices;
    • policy implementations do not keep unrecorded mutable RNG state;
    • named substreams isolate selection, allocation, mutation, and evaluation randomness;
    • replay consumes recorded decisions, while decision reproduction reconstructs the exact RNG substream observed by the original policy.

    SearchState.randomness exposes those named deterministic streams. It is not a process-global random generator.

    Composable policy pieces

    Most search algorithms should be configurations of small policies rather than new coordinators:

    search = meta.Search(
    selector=meta.Best(),
    allocator=meta.RoundRobin(proposers),
    operator=meta.Patch(),
    archive=meta.TopK(k=1),
    stop=meta.TrialLimit(50),
)

    The common pieces are:

    Policy Responsibility
    Selector Choose parent artifacts from committed state.
    Allocator Choose a proposer and assign bounded compute.
    OperatorPolicy Choose patch, rewrite, merge, replicate, train, or another typed operation.
    ContextPolicy Push a bounded context bundle before execution.
    ArchivePolicy Admit, reject, retain, or evict evaluated artifacts.
    StopPolicy Stop from budget, success, convergence, or explicit cancellation.
    MigrationPolicy Exchange candidates between populations when configured.

    These policies are explicit and versioned. meta.Search can implement next by composing them. Algorithms that need custom behavior can implement SearchProgram directly without replacing execution or persistence.

    Independent best-of-N

    Best-of-N always expands the seed and retains the best evaluated result:

    best_of_n = meta.BestOfN(max_trials=20)

    The shipped preset uses policy reference best-of-n@1. The seed evaluation participates in the same stable top-1 result view but does not count toward max_trials; ties retain the earliest successful evaluation, and failed proposals or evaluations are not rankable. Every successor has the seed as its only parent, so successful candidates form a star rather than an improvement chain.

    The future composed spelling of the same policy is:

    best_of_n = meta.Search(
    selector=meta.SeedOnly(),
    allocator=meta.RoundRobin(proposers),
    operator=meta.IndependentProposal(),
    archive=meta.TopK(k=1, objective="score"),
    stop=meta.TrialLimit(n=20),
)

    Conceptually:

    for _ in range(n):
    candidate = await trial(parent=seed)
    archive.consider(candidate)

return archive.best()

    The conceptual loop is useful for understanding the algorithm. The actual implementation uses next(state) so a run can resume after any committed trial.

    Greedy improvement

    Greedy search expands the current incumbent and retains a candidate only when it is better under the declared objective and constraint policy:

    greedy = meta.Search(
    selector=meta.ArchiveBest(),
    allocator=meta.RoundRobin(proposers),
    operator=meta.Mutate(),
    archive=meta.TopK(k=1, require_improvement=True),
    stop=meta.AnyOf(
        meta.SuccessReached(),
        meta.TrialLimit(50),
        meta.NoImprovement(10),
    ),
)

    Its custom next implementation, if needed, remains small:

    class Greedy(SearchProgram):
    archive = TopK(k=1, require_improvement=True)

    def next(self, state):
        if self.stop(state):
            return Stop("budget, success, or plateau")

        return TrialSpec(
            task_id=state.task_id,
            parent_ids=(state.archive.best().artifact_id,),
            proposer=self.allocator.choose(state),
            operator=self.operator.choose(state),
            context_policy=self.context,
            budget=self.allocator.budget(state),
        )

    Population and evolutionary search

    Population search changes the selector and archive, not the execution loop. The shipped steady-state preset is:

    population = meta.Population(size=3, tournament_size=2, max_trials=20)

    The preset uses policy reference population@1. It retains explicit, rank-ordered top-size membership through one record-only ArchiveUpdate per evaluation, always processing the final evaluation before it stops. Parents come from a tournament: tournament_size distinct members are drawn from the named selection stream — a self-contained integer draw, so recorded decisions reproduce on any Python version — and the highest-ranked sampled member is expanded. Score ties retain the earlier evaluation, and failed proposals or evaluations are rejected rather than scored. Because parents must be admitted members, a run whose seed evaluation fails stops with population_empty instead of expanding a non-member seed; Greedy and BestOfN instead fall back to the seed. Membership grants no promotion authority: run.best() remains the derived result view.

    The future composed spelling of richer population policies is:

    population = meta.Search(
    selector=meta.Tournament(size=3),
    allocator=meta.AdaptiveRoundRobin(proposers),
    operator=meta.WeightedChoice(
        mutate=0.75,
        crossover=0.20,
        restart=0.05,
    ),
    archive=meta.TopK(k=32, diversity_key="strategy"),
    stop=meta.TrialLimit(500),
)

    A crossover decision simply names several parents:

    return TrialSpec(
    task_id=state.task_id,
    parent_ids=(parent_a.id, parent_b.id),
    proposer=proposer,
    operator=OperatorSpec(kind="merge"),
    context_policy=context_policy,
    budget=trial_budget,
)

    No shared mutable checkout is required. The proposer receives private materializations of immutable parent artifacts and produces one successor.

    Islands and migration

    An island model is a view over several populations plus an occasional typed migration decision:

    class Islands(SearchProgram):
    archive = IslandArchive(count=4, capacity=16)

    def next(self, state):
        if state.step > 0 and state.step % 100 == 0:
            return MigrationSpec(
                sources=state.islands,
                topology="ring",
                count=2,
            )

        island = state.islands[state.step % len(state.islands)]
        parent = tournament(island.members, state.randomness)
        return TrialSpec(
            task_id=state.task_id,
            parent_ids=(parent.id,),
            proposer=choose_proposer(island, state),
            operator=OperatorSpec(kind="mutate"),
            context_policy=DiversityPreserving(),
            budget=state.budget.next_trial(),
        )

    The migration event changes projected membership; it does not move mutable files between directories.

    Experience-aware agents

    Search chooses where to expand. Context policies and the ExperienceReader determine how prior experience reaches an agent:

    run = meta.run(
    task=task,
    seed=seed,
    proposer=agent,
    search=meta.Greedy(max_trials=50),
    context=meta.AncestorsOnly(max_records=20, max_chars=8_000),
    experience=meta.PullAccess(
        max_operations=20,
        max_results=20,
        max_records=100,
        max_chars=32_000,
    ),
)

    M3.2 ships NoMemory, AncestorsOnly, and BestSibling. None and NoMemory() normalize completely away. A non-default policy adds a serialized ContextSpec segment to run identity, is declared after bootstrap, and stamps only successor TrialSpec values. M3.3 appends ExperienceSpec after that segment when PullAccess is declared.

    Under durable-local (Milestone 4.5) the declared ContextSpec/ExperienceSpec are folded into the run's atomic genesis batch and each selected context bundle and audited experience operation commits durably, so an interrupted run resumes to the same logical result: resume rebuilds the context policy from the registry and the experience bounds from the recorded ExperienceSpec (see the resume description above). This requires the context policy be a registered, deterministic, source-digestible component; the shipped presets satisfy that bar.

    Inside a capable proposer:

    def improve(parent, context):
    failures = context.experience.search(
        record_kinds=("outcome", "evaluation"),
        failure_kinds=("proposer_failure", "evaluator_failure"),
        limit=5,
    )
    trials = context.experience.search(record_kinds=("trial",), limit=2)
    comparison = context.experience.compare(
        trials.references[0],
        trials.references[1],
    )
    return revise(parent, failures.records, comparison.deltas)

    Every attempt and exact returned value is audited. The proposer may inspect only the scope and logical time granted to its trial. M3.3 enforces logical-time bounds, read budgets, and exact observation recording because these prevent future-information leakage. Principal identity, licensing, and multi-tenant visibility enforcement belong to later trust milestones.

    The combined lifecycle is PolicyDecisionMade → PolicyDecisionExplained → ContextSelected? → ExperienceGrantIssued? → (ExperienceOperationAttempted → resolution)* → ProposalSubmitted. Each grant is strictly prior at trial.logical_step - 1. A caller may narrow as_of but cannot widen it. Record/result limits and canonical rendering are independently prefix-bounded; all pull usage is cumulative within the grant and separate from task Usage. Every valid attempt is charged before validation and resolves to an exact committed success, opaque denial, or content-free budget exhaustion. Reproduction returns committed bundles and operation outcomes without rerunning selectors, traversal, filtering, comparison, or rendering.

    M3.4 adds an ordered ProposalResult.derived_from tuple. Live completion and replay validate it through one pure contract against the exact committed observation ledger: pushed bundle references first, then each successful pull result and its structured record references in operation order — comparison records in their committed interleaved rendering order — with first-occurrence deduplication. Invalid authority becomes an opaque PolicyViolation; resource exhaustion has precedence and neither coordinator-imposed failure commits an artifact or edge. Legitimate typed proposer failures and independently failed evaluations may retain valid edges.

    Run.experience_usage() and RunSummary.experience_usage aggregate push and pull channels without charging task resources. Summaries retain exact context and pull specs, while comparisons permit different memory strategies and report whether each declaration matches. Empty derivation uses omitted-default canonical encoding, preserving all pre-M3.4 proposal and event bytes without a schema-version change. The runnable examples/03_experience_reuse/ experiment compares all four memory variants under identical non-memory declarations and budgets.

    Inner and outer loops

    “Inner” and “outer” describe a relationship between runs; they are not separate engines.

    outer run optimizes a HarnessArtifact or PolicyArtifact
    ↓ evaluates one outer candidate through an episode suite
inner runs optimize or solve ordinary task artifacts
    ↓ return evidence and aggregate measurements
outer evaluator returns measurements and evidence
    ↓ outer archive or promotion policy admits or rejects

    Conceptually, a harness outer loop is only:

    for candidate_harness in outer_search:
    episodes = []

    for task in heldout_tasks:
        episodes.append(
            meta.run(
                task=task,
                seed=task.seed,
                proposer=candidate_harness,
                search=inner_search,
                budget=inner_budget,
            )
        )

    outer_evaluation = aggregate(episodes)
    outer_archive.consider(candidate_harness, outer_evaluation)

    The actual outer search is still implemented through next(state), and EpisodeSuite records each inner run, aggregation input, and budget. The loop above exposes the relationship without implying that a Python iterator is durable state.

    An inner run improves an artifact under a particular harness or search policy:

    inner_spec = meta.RunSpec(
    task=repository_task,
    seed=repository_seed,
    proposer=candidate_harness,
    search=meta.Greedy(max_trials=20),
    budget=Budget(evaluations=20, tokens=500_000),
)

    The outer task treats the harness itself as the candidate artifact:

    harness_task = meta.Task(
    artifact_kind="harness",
    evaluator=meta.EpisodeSuite(
        tasks=heldout_repository_tasks,
        build_inner_run=lambda harness, task: inner_spec.replace(
            task=task,
            proposer=harness,
        ),
        aggregate=meta.MeanAndFailureRate(),
        episode_budget=Budget(evaluations=20, tokens=500_000),
    ),
    objectives=[
        meta.Maximize("heldout_correctness"),
        meta.Minimize("mean_tokens"),
    ],
)

outer_run = meta.run(
    task=harness_task,
    seed=baseline_harness,
    proposer=harness_mutator,
    search=meta.Population(size=8, max_trials=40),
    budget=Budget(evaluations=40),
)

    The closure is valid in local mode, where the run is marked non-portable and may not survive process restart. durable-local and distributed modes require a versioned inner-run factory or manifest rather than an anonymous Python closure. InnerRunTemplate is a validated typed object model, not a separate stringly typed template language.

    The outer candidate may change only declared harness surfaces. It cannot change held-out tasks, evaluator code, episode budgets, secrets, permissions, audit history, or promotion rules.

    Policy meta-evolution

    Policy evolution uses exactly the same nesting. The candidate artifact is now a serialized search policy:

    policy_task = meta.Task(
    artifact_kind="search-policy",
    evaluator=meta.EpisodeSuite(
        tasks=heldout_task_distribution,
        build_inner_run=meta.InnerRunTemplate(
            seed=meta.TaskSeed(),
            proposer=worker_agent,
            search=meta.CandidatePolicy(),
            budget=Budget(evaluations=50),
        ),
        aggregate=meta.RobustAggregate(
            metrics=["best_score", "cost", "failure_rate"],
        ),
    ),
)

meta.run(
    task=policy_task,
    seed=baseline_policy,
    proposer=policy_mutator,
    search=meta.BestOfN(max_trials=20),
)

    The outer BestOfN is not the policy being evaluated. It chooses among policy candidates. Each candidate controls fresh inner episodes, and its score comes from held-out outcomes under an independent outer evaluator.

    Budget nesting

    Every loop has a separate budget boundary:

    outer run budget
└── number of harness or policy candidates evaluated
    └── episode-suite budget per candidate
        └── inner run budget per task and seed
            └── trial budget per proposer execution

    Unused inner budget does not become outer authority. A candidate cannot raise any enclosing budget. Cache reuse is valid only when task, candidate, evaluator, environment, seed, data split, and relevant budget semantics match.

    Scientific experimentation

    class ScientificSearch(SearchProgram):
    archive = EvidenceArchive()

    def next(self, state):
        if state.claims.need_replication():
            return ReplicationSpec(
                experiment=state.claims.highest_value_unreplicated(),
                independent_environment=True,
            )

        return TrialSpec(
            task_id=state.task_id,
            parent_ids=state.claims.relevant_artifacts(),
            proposer=state.proposers.choose_role("experiment-design"),
            operator=OperatorSpec(kind="experiment"),
            context_policy=ContradictionsAndEvidence(),
            budget=state.budget.next_trial(),
        )

    Simulation or execution evidence updates a scoped claim; it does not automatically become a validated scientific discovery.

    The simplicity test

    A new use case should normally require only:

    artifact_codec = ...
task = Task(evaluator=...)
proposer = ...
search = ...

meta.run(task=task, seed=seed, proposer=proposer, search=search)

    It should not require:

    if artifact.type == "my-new-domain":
    coordinator.do_something_special()

    When an algorithm does not fit next(state) -> SearchDecision, first ask whether it needs a generally useful typed decision such as replication, migration, merge, training, or human review. Add such a decision only when its transition, authority, budget, and event semantics are clear.
