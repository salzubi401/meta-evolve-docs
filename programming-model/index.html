    Meta-Evolve Programming Model

    Status

    Status: Shipped. This is the canonical contract for the public API available from the current package. The generated API reference owns signatures and parameter details; the guides below own task-oriented usage. Milestone 9 is shipped. The deterministic M8.1–M8.5 implementation is in the package; final M8 closure remains Experimental/live-only. The first authorized official-SDK capture is retained, but it failed schema validation before returning a native mutation, so it did not satisfy M8.6.

    Milestone 5 is complete: immutable source trees, exact patches, bounded local processes, and independent command evaluation compose through the same callable path. Milestone 7 completes the cross-domain extension boundary. User-owned SDK wrappers use that same callable path; no first-party provider adapter is shipped.

    The smallest useful mental model

    A run has five inputs:

    Task       what better means and which evaluator decides
Seed       the initial immutable artifact
Proposer   how a successor is suggested
Evaluator  independent measurement, normally declared by Task
Search     which parent receives the next unit of work

    The ordinary path stays small:

    import meta_evolve as meta

items = ("outline", "draft", "review")

def complete_one(completed, _context):
    return (*completed, items[len(completed)])

task = meta.Task(evaluator=lambda completed: len(completed))
result = meta.run(
    task=task,
    seed=(),
    proposer=complete_one,
    search=meta.Greedy(max_trials=3),
)

print(result.best())

    The returned Run is both the result and the query surface for trials, lineage, evidence, usage, failures, summaries, and comparisons.

    Canonical public surface

    The package root exports 53 shipped names. The curated reference partitions them into everyday runs, evaluation/source execution, experience, and durability/inspection/errors. Root imports are the public surface; kernel records remain internal unless a guide explicitly describes an extension protocol.

    The constructible harness family stays under meta_evolve.harness: HarnessArtifact, HarnessMutation, MutationSurface, TextParam, PolicyParam, MutationApplication, portable repository episodes, comparison views, and export views. Only compare_harnesses, export_harness, and load_harness are root conveniences.

    The neutral MutationApplication and MutationSurface contracts live under meta_evolve.mutation; harness keeps compatibility re-exports. The data-only M9 family lives under meta_evolve.policy: PolicyArtifact, its two fixed surfaces and mutation, CandidatePolicy, portable episodes/suites, captured outcomes/evaluations, and comparison views. compare_policies is the single root convenience.

    Shipped guides

    • Runs and results — the callable story and query views.
    • Evaluation and budgets — objectives, evidence, usage, and typed failures.
    • Experience — no memory, pushed context, audited pull, and derivation.
    • Durability — storage, reopen, recovery, and resume.
    • SDK integration — user-owned callable wrappers and audited tools.
    • Command line — run, list, inspect, resume, and compare.
    • Extensions — codecs, registries, component identity, and conformance.
    • Policy evolution — trusted policy artifacts, nested capture, and held-out comparison.

    Execution profiles

    local accepts live Python components and defaults to isolated in-memory storage. durable-local requires durable storage plus registered, reconstructible components and records enough identity to resume honestly. The proposed distributed profile is design material, not a shipped execution mode.

    Authority and failure boundary

    Candidates may propose artifact content. They cannot change the evaluator, effective budget, permissions, hidden data, audit history, or promotion rule. Invalid output, proposer/evaluator failure, timeout, exhaustion, policy violation, and infrastructure failure remain typed, inspectable outcomes. A failure with no valid measurement is never ranked as a low score.

    Harness candidates receive a second, trusted check after codec encoding and before artifact creation. The built-in harness codec compares the encoded successor with its one parent and rejects changed component references, interfaces, parameter names or types as PolicyViolation; malformed and no-op transitions are InvalidOutput. Wrapper-side mutation helpers are convenience, not authority.

    Budget nesting

    Single-run accounting is in evaluation and budgets. M9's captured nested accounting is in the policy-evolution guide: inner trials and evaluations remain inner usage, while only tokens and elapsed time roll up.

    Other workflows through the same loop

    Shipped text, source, skill-set, and custom domains use the same meta.run() boundary. Scientific and network directions are explicitly separated under Design.

    The simplicity test

    A common use case should remain one task, one seed, one proposer, one search declaration, and one meta.run() call. New internal protocols must not make that public story larger.
