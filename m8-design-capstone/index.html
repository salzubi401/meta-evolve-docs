    M8 design capstone

    Design this one bounded experiment:

    Start from a worker harness with a planner prompt and context policy. Let an outer proposer change only those two surfaces. Score each candidate on fresh held-out repository tasks under equal budgets. Compare it with the unchanged harness, then leave promotion to an external decision.

    Write a decision-complete proposal for issue #8. Do not add runtime types, package directories, or placeholder examples. M8 is the next milestone; this capstone is design only.

    Map the design onto current seams

    M8 concept Existing seam to extend Required design decision
    HarnessArtifact Artifact kind/representation plus ArtifactCodec and Registry Define a typed manifest of component references and declared interfaces; preserve composite content identity and occurrence lineage
    MutationSurface Proposer result validation, codec validation, workspace capture, and policy violations Name mutable prompt and context-policy fields; reject changes to evaluator, tasks, secrets, permissions, budgets, history, and promotion
    Held-out evaluation Evaluators that launch bounded inner meta.run calls, as demonstrated by skill evolution Define a portable versioned episode suite, fresh inner runs, explicit nested seeds and budgets, and aggregate evidence
    Harness comparison Run.compare, summaries, usage, typed failures, and evaluator component identity Compare baseline and candidate under compatible tasks, suites, budgets, models, and environments; expose quality, cost, and failure behavior
    External promotion Search records a best result but grants no production authority Specify a separate governance-owned promotion rule and record; never let a candidate or evaluator deploy itself

    The M8 milestone owns the goal, deliverables, acceptance gate, and out-of-scope list. The architecture owns authority. The inner and outer loop sketch owns the target relationship, not a shipped API promise.

    Required design answers

    Artifact and identity

    • What exact fields make up the harness manifest?
    • Which fields affect the HarnessArtifact content digest?
    • How do two occurrences with equal content retain distinct causal identity?
    • How are every component reference and its behavior-affecting configuration made visible to comparison and replay?

    Mutation authority

    • What two paths or typed parameters may the first proposer change?
    • Which validator rejects a change outside the MutationSurface?
    • How does rejection remain an inspectable typed outcome without creating a successor artifact?
    • Why can the candidate never alter the held-out suite, evaluator, permissions, enclosing budgets, audit history, or promotion rule?

    Held-out evaluation and budgets

    • What is the portable episode-suite representation and version boundary?
    • How is each inner run guaranteed fresh rather than reused from candidate state?
    • Which nested seeds, evaluation/trial/token/wall budgets, environments, and cache keys are declared?
    • How are episode failures retained without averaging them into low scores?

    Comparison and promotion

    • Which declarations must match between the baseline and candidate experiment?
    • Which quality, cost, robustness, and typed-failure views are reported?
    • What evidence is sufficient for an external promotion decision?
    • Where is the explicit handoff from search selection to governance, and how is a rejected promotion retained?

    Replay and extension seams

    • Which new durable facts are required, and can existing batch grammar express them without a coordinator branch on harness type?
    • Can replay rebuild every decision without rerunning an inner episode?
    • Which independently testable port needs a reference adapter?
    • What conformance suite proves a second mutation surface can plug in without changing the coordinator?

    Current blockers

    1. Custom codecs are local-only. A live registered codec has no verified manifest, so a custom HarnessArtifact cannot yet enter honest durable-local resume.
    2. No portable episode-suite representation exists. Current nested examples close over local Python episode lists; M8 needs a versioned representation or factory before durable replay.
    3. Conformance coverage remains incomplete. Published suites cover codecs and repository proposers, while evaluator and context-policy suites are still missing and tracked by #98.
    4. Hidden configuration requires explicit component identity. Models, episode names, timeouts, environments, and other behavior-affecting closure state must enter a component version or manifest before comparison is valid.

    Do not solve one by hiding it. A local-only prototype must say local-only. A name-only closure must appear as name-only. A missing suite must remain a tracked acceptance risk.

    Acceptance evidence to propose

    • Valid planner-prompt and context-policy mutations pass through one ordinary meta.run coordinator path.
    • Attempts to change hidden evaluation, permissions, budgets, or promotion are typed rejections with no successor artifact.
    • Composite digest, distinct occurrence identity, parent lineage, and component provenance are deterministic and replayed from committed records.
    • Every candidate is evaluated on fresh held-out inner runs with exact nested usage and typed failures.
    • Baseline comparison refuses mismatched suite, model, environment, or budget identity before ranking.
    • Resume reaches the same logical result without rerunning committed episodes.
    • A second mutation-surface implementation passes the same conformance suite without a coordinator special case.
    • Promotion remains an explicit external outcome, never an automatic side effect of best().

    Final review

    Your proposal is ready only if a reviewer can answer all of these from it:

    • Who owns each mutable field and each fixed control?
    • What gives artifacts, components, episodes, and runs their identities?
    • Where are parent lineage and derived observations recorded?
    • Which layer charges every unit of nested work?
    • Which failures have no score, and where are they retained?
    • What can replay reconstruct without external execution?
    • What makes the baseline comparison scientifically valid?
    • Who may promote the winner, using what recorded evidence?

    If any answer depends on “the implementation will know,” expose the declaration or boundary that makes it checkable.
