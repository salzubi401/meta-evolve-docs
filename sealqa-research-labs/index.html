    SealQA research labs

    Status: Experimental/live-only. The frozen substrate inspection below is captured, but every provider-backed research cycle remains live-only.

    This is a standalone guide to four small evaluated-improvement mechanisms. You do not need to open a notebook to understand the experiments. The notebooks are optional executable companions linked from each chapter.

    The labs ask one recurring question:

    How can an agent improve a prompt, data recipe, local harness, or reusable skill while evaluation, budgets, hidden answers, and promotion remain outside the candidate's control?

    They use eight frozen LongSeal examples because LongSeal combines a concrete question with one useful document hidden among conflicting or irrelevant documents. That makes failures easy to inspect: the agent may retrieve the wrong fact, trust stale evidence, combine incompatible documents, or format the right fact incorrectly.

    These are teaching implementations. They do not reproduce the cited papers, publish an official SealQA score, or establish that one method improves Claude.

    The common experimental substrate

    All four labs share the same declarations:

    Declaration Value Why it matters
    Provider Claude The shipped adapter has measured interruption support.
    Model claude-haiku-4-5-20251001 Every arm uses one pinned model identity.
    max_turns 50 Bounds an ordinary agent session.
    pull_max_turns 50 Gives pull-enabled sessions the same turn ceiling.
    Adapter timeout 1,800 seconds Requests interruption after 30 minutes.
    Inner wall budget 1,860 seconds Leaves one minute for adapter and coordinator cleanup.
    Live opt-in META_EVOLVE_LIVE_CLAUDE=1 Prevents CI or casual imports from spending money.

    You can verify the deterministic boundary without credentials or a provider call:

    uv run python examples/18_sealqa_research_labs/inspect_substrate.py
    Output
    sessions: {'feedback_descent': 5, 'autodata': 7, 'meta_harness': 4, 'evoskill': 8}
total sessions: 24
inner bounds: turns=50 timeout=1800 wall=1860
solver fields: ('id', 'question', 'documents', 'metadata')
hidden answer visible: False

    Each Claude call is one ordinary inner meta.run over a SourceTree workspace:

    public workspace + instructions + JSON schema
                    │
                    ▼
             one Claude session
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
 structured value       typed failure
 evidence + usage       no rankable metric

    The outer lab is plain Python orchestration. It has no aggregate wall budget because all provider work is already bounded by the inner sessions; its local grading and validation are deterministic and tested.

    How the shared components actually work

    The labs are small because they reuse one session adapter and change only the outer dataflow. A SessionRequest contains five explicit inputs:

    label         durable human-readable role, such as feedback.editor
instructions  what this one agent session may do
schema        the exact JSON object it must return
workspace     candidate-visible SourceTree files
experience    optional bounded read grant over prior evidence

    ClaudeSessionRunner.run(request) converts that request into an ordinary Meta-Evolve run:

    meta.run(
    task=meta.Task(
        evaluator=session_evaluator,
        artifact=meta.SourceTree,
        objectives=(meta.Maximize("completed"),),
        budget=INNER_BUDGET,
    ),
    seed=request.workspace,
    proposer=bounded_claude_agent,
    search=meta.Greedy(max_trials=1),
    experience=request.experience,
)

    Here the inner evaluator answers only “did this session complete and retain its declared structured output?” Algorithm-specific scoring happens afterward in evaluator-owned Python. This separation prevents the model from deciding whether its answer, generated item, prompt edit, harness edit, or skill is good.

    The returned SessionRecord contains exactly one of a structured value or a typed failure, plus provider evidence, usage, and pull counters. Independent schema validation runs even for injected test transports, so tests and live execution cannot disagree about what counts as valid output.

    One cycle, phase by phase

    Three different counters are easy to confuse in these labs:

    • A phase is a step in the outer research algorithm, such as measuring a seed, proposing a successor, or comparing two artifacts.
    • A session is one Claude call. Each session is wrapped in its own inner meta.run.
    • A trial belongs to that inner run. Greedy(max_trials=1) means the session gets one bounded proposal attempt; it does not turn the outer lab into a repeated greedy search.

    The common path through one improvement cycle is:

    phase 0              phase 1                    phase 2
declare artifact ──► build SessionRequest ──► inner meta.run
and fixed controls    from allowed evidence     Greedy(max_trials=1)
                                                       │
                                                       ▼
phase 5              phase 4                    phase 3
retain LabResult ◄── measure successor ◄──── propose successor
and comparison        with fixed evaluator       from SessionRecord evidence

    The two artifact layers have different jobs. The outer artifact is the research object being improved: a meta.Text, SourceTree, or SkillSet. Every provider call then receives an inner workspace artifact, always a SourceTree, containing only the files allowed for that role. For example, a Feedback Descent editor receives a SourceTree with prompt.md and feedback.md, then its structured output is lifted into the successor meta.Text.

    Step by step, the reusable components do this:

    1. Outer Python selects an immutable artifact and evaluator-owned controls.
    2. It projects only allowed observations into a SessionRequest workspace or bounded experience grant.
    3. ClaudeSessionRunner executes one inner meta.run; the inner evaluator records completion, structured output, evidence, usage, or a typed failure.
    4. Outer evaluator code grades the record or applies a deterministic gate.
    5. If the algorithm calls for a change, another request converts that evidence into a successor outer artifact.
    6. The fixed evaluator measures the successor, and LabResult retains sessions, artifacts, measurements, lineage, and usage.

    The four labs instantiate that path differently:

    Lab Initial observation Successor proposal External comparison
    Feedback Descent Answers from two seed prompts Edit the preferred prompt from textual feedback Exact-grade the edited prompt on the same development case
    AutoData Generator and solver behavior for the seed recipe Rewrite the recipe from the deterministic acceptance report Run the same generation-and-probe protocol on the successor
    Meta-Harness precursor Baseline diagnostic answer and trace Replace allowlisted files in the harness SourceTree Evaluate parent and successor on the same unseen row
    EvoSkill Two externally graded induction records Analyze bounded experience, then build a SkillSet Compare baseline and skill arms on two held-out rows

    This is one bounded improvement cycle per lab, not several optimizer iterations. A dependent typed failure stops the remaining phases when no valid successor or comparison can be constructed, and the runner never retries until an improvement appears.

    The outer lab then supplies the research algorithm by connecting these generic pieces:

    Principle Concrete component
    What may change? meta.Text, SourceTree, or SkillSet artifact
    How is a change proposed? One schema-constrained session request
    What observations guide it? Explicit workspace files or bounded experience
    What counts as success? Evaluator-owned exact grade or deterministic gate
    Which work is retained? LabResult sessions, artifacts, measurements, usage
    What stops runaway work? Session arithmetic plus turn, timeout, and wall bounds

    That is how a research idea becomes a small algorithm here: choose the mutable artifact, decide which recorded observation reaches the next proposer, keep measurement external, and spell out the comparison. The four chapters differ mainly in those connections—not in a new framework for each paper.

    Why Claude, and why Haiku

    Two separate decisions sit behind the provider row above.

    Claude rather than Codex. Every lab requires a finite adapter timeout so a stuck session becomes a typed failure instead of an unbounded bill. The shipped Claude adapter accepts timeout_seconds alongside a finite inner wall budget. The Codex adapter refuses this contract by design: it rejects finite wall budgets because native interruption does not verify descendant cleanup (src/meta_evolve/adapters/codex_proposer.py, measured in experiments/06_sdk_capabilities/). Separately, OpenAI has announced that GPT-5.4 and GPT-5.4 mini retire from ChatGPT-authenticated Codex on August 31, 2026, which would strand a committed capture pinned to those models.

    Haiku rather than a larger Claude model. Every Claude model receives the same adapter guarantees, so this is purely a cost decision: the worst case is 24 sessions of 30 minutes each. The pinned ID follows Anthropic's documented model-version scheme. Overriding the model is allowed but enters evaluator identity, so results from an overridden run cannot be silently compared against a committed capture.

    What is frozen and what may change

    The fixture assigns exactly one role to each row:

    Rows Evaluator-owned role
    1 Feedback Descent development case
    2 AutoData grounding case
    3 Meta-Harness diagnostic case
    4 Meta-Harness unseen validation case
    5–6 EvoSkill induction cases
    7–8 EvoSkill held-out cases

    The artifact being improved changes from lab to lab:

    Lab Mutable artifact Fixed outside candidate authority
    Feedback Descent meta.Text solver prompt Question, documents, answer, comparator, budget
    AutoData meta.Text generation recipe Frozen evidence, quality checks, budget
    Meta-Harness precursor planner.md, context_policy.json in a SourceTree Validation row, permissions, budgets, history, promotion
    EvoSkill one Markdown document in meta.SkillSet Held-out rows, base agent, grader, budget

    This is the core Meta-Evolve authority boundary: a candidate may propose a new artifact, but it cannot score itself, reveal hidden evaluation, enlarge its budget, rewrite history, or promote itself.

    Leakage boundary

    The committed fixture contains evaluator-only fields so local exact grading is possible. Solver and proposer views deliberately remove:

    • the reference answer;
    • source and gold URLs;
    • upstream document IDs and gold-document labels;
    • the row's teaching role or split assignment.

    Solvers receive stable local IDs such as doc-01, plus document title, date, and text. A gold document can therefore be present in the evidence without a flag that tells the solver which one it is.

    Feedback Descent's comparison session is an evaluator, so it may see the hidden reference answer. The prompt editor never sees it. AutoData's generated reference_answer is created by the generator for a synthetic item; it is not the hidden answer of the frozen SealQA row.

    Failure and scoring semantics

    The labs use normalized exact-answer grading: Unicode is normalized, casing is folded, and repeated whitespace is collapsed. The remaining text must match exactly. This is intentionally simple and deterministic; it is not SealQA's official evaluation method.

    A valid answer produces a metric such as:

    {"exact": 1.0}  # normalized exact match
{"exact": 0.0}  # valid answer, but wrong

    The following outcomes have no metric and cannot be ranked:

    • malformed structured output;
    • missing or unchanged proposal where an edit is required;
    • timeout or turn exhaustion;
    • provider or infrastructure failure;
    • policy violation, such as editing a protected harness control.

    That distinction matters. “The model answered incorrectly” is evidence about the artifact; “the provider timed out” is not a low-quality answer.

    Evidence, lineage, and identity

    Every session retains its label, structured value or typed failure, provider evidence, token/wall usage, and experience-use counters. Each lab also records the relationship between artifacts:

    seed artifact ── evidence-guided proposal ──► successor artifact
      │                                          │
      └──────── evaluator-owned score ───────────┘

    Behavior-affecting declarations enter identity: model, instructions, structured schema, turn limits, adapter timeout, inner budget, workspace digest, evidence digest, pull bounds, fixture-row checksum, and grading mode. A comparison can therefore detect configuration drift instead of silently ranking different experiments.

    How to run the curriculum

    From the repository root:

    uv sync --extra claude --group dev
# Authenticate Claude Code using its supported login flow.
META_EVOLVE_LIVE_CLAUDE=1 uv run --extra claude \
  python examples/18_sealqa_research_labs/run_all.py all

    Replace all with feedback_descent, autodata, meta_harness, or evoskill to run one chapter. The command makes paid provider requests. It does not retry until an improvement appears.

    Current capture status

    No live output is claimed yet. The implementation and deterministic tests are complete, but no credentialed 24-session output has been committed. The build environment did not have the explicit live opt-in. Consequently, these chapters explain what every result means without inventing an observed improvement.

    The first authorized capture should be run once and preserved honestly. A tie, regression, typed failure, unused experience record, or null result is part of the finding—not a reason to rerun until the story looks better.

    Recommended reading order

    1. Feedback Descent: improve a prompt from structured textual feedback.
    2. AutoData: improve a synthetic-data recipe using solver behavior and deterministic gates.
    3. Meta-Harness precursor: widen the mutable artifact while enforcing an explicit authority boundary.
    4. EvoSkill: convert recorded failures into a reusable skill and evaluate only on held-out rows.

    The Meta-Harness chapter is a pre-M8 teaching precursor. M8 remains the sole owner of HarnessArtifact, MutationSurface, portable episode suites, replay, and promotion. Update or retire the lab when M8 ships; see the M8 design capstone.
