    User-owned SDK integration

    Status: Shipped. Any SDK integrates through the same callable boundary as deterministic Python. Meta-Evolve does not install, authenticate, configure, or wrap a model SDK.

    Start with the ordinary callable

    import meta_evolve as meta

def propose(parent: meta.Text, context: meta.ProposerContext) -> meta.Text:
    response = my_sdk.generate(
        input=parent.value,
        context=[item.rendered for item in context.bundle.items],
    )
    return meta.Text(response.output_text)

run = meta.run(
    task=meta.Task(evaluator=lambda text: len(text.value)),
    seed=meta.Text("draft"),
    proposer=propose,
)

    The wrapper owns SDK authentication, session lifecycle, tools, permissions, structured decoding, retry policy, and provider-specific telemetry. Return the decoded artifact value directly when that is all the run needs.

    Return a typed result

    Use ProposalResult when the wrapper has more to report:

    def propose(parent, context):
    response = my_sdk.generate_structured(input=parent)
    return meta.ProposalResult(
        candidate=response.artifact,
        usage=meta.Usage(
            tokens=response.input_tokens + response.output_tokens,
            wall_seconds=response.elapsed_seconds,
        ),
        metadata={"model": response.model},
        evidence=(
            meta.EvidenceDraft(
                kind="sdk-response",
                data={"cost": response.cost, "raw": response.raw},
            ),
        ),
    )

    Only total tokens and elapsed time enter shared Usage. Cost, model identity, granular token categories, and raw provider telemetry belong in evidence or metadata. Trial and evaluation counts are coordinator-owned; reporting either produces typed InvalidOutput.

    Ordinary SDK exceptions become ProposerFailure. Framework failures about durable state, accounting, or run capability escape unchanged: EventStreamConflict, DurableCorruption, InvalidSearchHistory, ExperienceStoreUnavailable, ExecutionAccountingUnknown, and CapabilityError.

    Give an SDK audited pull tools

    When an SDK supports custom tools, register a user-owned handler that delegates to context.experience:

    used = []

def search_experience(arguments):
    if context.experience is None:
        raise meta.ExperienceAccessDenied("pull access was not granted")
    observation = context.experience.search(**arguments)
    used.extend(record.ref for record in observation.records)
    return observation

response = my_sdk.run(tools={"search_experience": search_experience})
return meta.ProposalResult(
    candidate=response.artifact,
    derived_from=tuple(dict.fromkeys(used)),
)

    The exact observation API is defined by ExperienceReader. The callback may run in process, or a user-owned RPC service may forward each request to this scoped handler and return its result. The RPC service must not cache or broaden the reader capability. Meta-Evolve adds no generic tool server or agent process.

    Access denial, exhaustion, audit-store failure, and unknown accounting retain their normal semantics because the SDK tool calls the authoritative reader. SDKs without custom-tool support can receive pushed context.bundle data, but that is context injection rather than agent-directed pull.

    The credential-free 06_user_owned_sdk example contains a complete deterministic fake SDK and audited tool callback. A maintainer may put an opt-in real-client smoke script under experiments/sdk_boundary_smoke/; it is not a shipped provider integration and must add no package dependency.

    Authority and reproducibility

    The wrapper may propose candidate content. It cannot choose the evaluator, change the run budget, grant itself experience, edit audit history, or promote a result. External evaluation and durable storage remain the sources of score, accounting, and lineage truth.

    Committed requests, evidence, usage, failures, and artifacts support inspection and replay. Meta-Evolve does not claim that a later external SDK call will regenerate byte-identical output.

    API details: ProposalResult, ProposerContext, and EvidenceDraft.
