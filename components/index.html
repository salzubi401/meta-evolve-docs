    Component map¶

    Ten seams in Meta-Evolve are replaceable. Each is a Protocol, so you implement it by writing a class or a function with the right shape — there is no base class to inherit and no plugin manifest to register in.

    This page is the index: what each seam decides, what ships for it, and where the contract lives in the source.

    Package Holds
    domain immutable records, identities and lineage, objectives, budgets, typed failures
    ports the Protocol seams every extension implements
    application the coordinator, sessions, read models, replay and recovery
    policies the search presets and the context policies
    harness the agent-harness artifact family
    policy the search-policy artifact family
    adapters callables, subprocesses, filesystem and SQLite stores, Git history
    presentation inert artifact previews and diffs
    browser the optional read-only local UI
    conformance the published test suites for extension authors

    Dependencies point inward. domain knows nothing about infrastructure, ports declares the seams, and adapters translates the outside world at the edge. The coordinator never branches on which implementation you supplied.

    The ten seams¶

    Seam Decides Protocol Ships
    Search which parent to expand, when to stop SearchProgram — domain/search.py Greedy, BestOfN, BestOfK, Population, Specialists, TreeSearch, @meta.search
    Codecs how a value becomes durable bytes ArtifactCodec — ports/codecs.py python-value, text, source-tree, skill-set, agent-harness, search-policy
    Proposers the proposed successor content Proposer, ProposerRunner — ports/proposers.py, ports/runners.py CallableProposer, PatchProposer
    Evaluators the measurement, independently Evaluator — ports/callables.py CallableEvaluator, CommandEvaluator
    Memory, pushed which prior records a proposal sees ContextPolicy — policies/context.py NoMemory, AncestorsOnly, BestSibling
    Memory, pulled what a proposer may ask for, under audit ExperienceAccess, ExperienceReader — ports/experience.py PullAccess, GitHistoryView
    Storage where artifacts and events live ArtifactStore, EventStore, CommitStrategy in-memory, filesystem blobs, SQLite, read-only
    Workspaces how an artifact becomes a directory WorkspaceProvider — ports/workspaces.py DirectoryWorkspaces
    Sandboxes how an external command runs SandboxProvider — ports/sandboxes.py DevelopmentSubprocessSandbox
    Mutation surfaces what a candidate may change on a typed artifact MutationSurface — mutation.py TextParam, PolicyParam, ParentSelection, TrialLimit

    Every one of these has a published conformance suite you can subclass to prove your implementation obeys the same contract the built-ins do — see Trust a shipped contract.

    Two names that look alike¶

    meta_evolve.policies holds search policies — the presets you pass as search=. meta_evolve.policy holds a search policy as an evolvable artifact, used when the thing being improved is the search strategy itself. Plural is the tool; singular is the subject.

    Seams that deliberately do not exist¶

    Knowing what is absent is as useful as knowing what ships:

    • No stopping-criteria component. Stopping is a Stop value returned from a search program, and satisfaction thresholds live on the objective, as in Maximize("score", satisfy=1.0).
    • No callback, hook, or telemetry component. Observability is structural: the event stream is the log, evidence attaches to results, and every decision records its own explanation.
    • No model provider or prompt-template component. Model calls live in code you own and pass in as a proposer. Prompts are ordinary artifacts, so a prompt is improved by the same loop as anything else. See SDK integration.

    Replacing one part¶

    Every seam is swapped the same way: build the object, pass it in, change nothing else.

    experiment = meta.Experiment(
    task=task,
    seed=seed,
    proposer=my_proposer,
    search=meta.BestOfK(k=4),
    context=meta.AncestorsOnly(),
)

    Passing an object directly is enough for ordinary runs. Durable, resumable runs additionally need a [Registry][meta_evolve.Registry] so each component has a stable name and a verified source digest — see Registry and component identity.
