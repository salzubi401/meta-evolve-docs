    Typed failures

    Failure values returned by (or attributed to) components import from meta_evolve.domain, not the root package. Only these exact classes are accepted where a failure is expected.

    The durable lifecycle vocabulary for policy authors and kernel code.

    The public names below follow an evaluated trial from identities and immutable values through task configuration, execution, and independent evaluation. Ordinary users need only the smaller surface re-exported at the package root. DURABLE_TYPES is the serialization decoder's internal closed allowlist.

    Failure dataclass

    Base shape of a typed, attributed failure record.

    A failure names what went wrong and who it is attributed to; it is never converted into a rankable score. Only the seven concrete subclasses are accepted wherever a failure is expected — the bare base class and user subclasses are rejected, so every recorded kind is one of a closed, queryable set. Failures are values (returned), not exceptions (raised).

    InvalidOutput dataclass

    Bases: Failure

    A component's output violated its contract (kind "invalid_output").

    Produced when a proposer returns an unencodable candidate or reports coordinator-owned usage, when an evaluator's return matches no accepted form or misses a required objective metric, or when a patch's expected bytes do not match the parent.

    ProposerFailure dataclass

    Bases: Failure

    The proposer itself failed (kind "proposer_failure").

    An exception raised inside a proposer callable is translated into this failure; infrastructure faults and CapabilityError escape instead of being attributed to the proposer.

    EvaluatorFailure dataclass

    Bases: Failure

    Measurement could not complete (kind "evaluator_failure").

    An exception raised inside an evaluator callable — or an abnormal grader process — is translated into this failure, attributed to the evaluator, never scored against the candidate.

    TimeoutFailure dataclass

    Bases: Failure

    Bounded work exceeded its declared time ceiling (kind "timeout").

    ResourceExhausted dataclass

    Bases: Failure

    A declared resource limit was reached (kind "resource_exhausted").

    PolicyViolation dataclass

    Bases: Failure

    Execution breached a declared policy (kind "policy_violation").

    InfrastructureFailure dataclass

    Bases: Failure

    The surrounding infrastructure faulted (kind "infrastructure_failure").

    Attributed to neither the candidate nor a component — retrying may succeed without any change to either.

    Generated entries

    Meta-Evolve: improve artifacts through proposed, evaluated, recorded trials.

    The root package keeps the simple callable path small: define a task, bound it with a budget, and state what to maximize or minimize. The full durable vocabulary for policy authors and kernel code lives in meta_evolve.domain, and canonical serialization lives in meta_evolve.serialization.

    BudgetUnavailable

    Bases: RunError

    The requested action cannot fit within its effective budget.

    CapabilityError

    Bases: RunError

    A run's declared or requested execution profile is not honored.

    Raised for unverifiable component implementations (lambdas, closures, functools.partial, decorated wrappers, or callables with no resolvable module source), unregistered (role, name, version) lookups, and durable-local configuration that lacks a registry, durable storage, or a registered evaluator/proposer/policy. Also raised when storage is asked for an optional capability its components do not declare, such as enumerating runs through a non-RunIndex event store.

    ContextPolicy

    Bases: Protocol

    Select the exact bounded context bundle pushed to one proposer call.

    Only records committed strictly before the candidate trial's logical step are eligible; context facts themselves are never eligible. The kernel rejects a bundle that selects anything else or exceeds the declared bounds.

    CommandEvaluator dataclass

    Materialize a source tree and trust a fixed 0/1/other exit protocol.

    The reference independent evaluator for SourceTree tasks: each candidate is written into a fresh workspace and the declared command runs over it in a sandbox. Exit 0 scores passing_score, exit 1 scores failing_score, any other exit is a typed evaluator failure — never a score. The process result and environment are attached as evidence. The evaluator owns its command, environment, timeout, and any hidden checks; the candidate cannot rewrite them.

    ExperienceReader

    Bases: Protocol

    The bounded read capability supplied only to successor proposers.

    When a run declares pull access, each proposal receives one reader as context.experience. Every operation is audited into the run record and counted against the declared bounds; all five operations observe only records committed strictly before the proposing trial. Exceeding a bound raises ExperienceBudgetExhausted; an unauthorized or unknown reference raises ExperienceAccessDenied.

    EvaluationResult dataclass

    Normalized independent metrics or a typed evaluator failure.

    Exactly one side is present: a successful evaluation requires at least one metric, and a failed one cannot carry rankable metrics. A plain evaluator callable may instead return a number or a mapping — both normalize into this type — but returning it explicitly is how an evaluator attaches evidence, uncertainty, or provider usage.

    runs()

    Every run this storage holds events for, sorted by id.

    Identities, not Run objects: opening a run validates and replays its whole stream, and detail is already Run.summary()'s job. A listing exists so those queries stay reachable once the ids have scrolled out of a terminal, so it returns exactly what reopening one needs. The order is lexicographic by id and identical across backends; run ids are content-derived, so it is not chronological.

    Enumeration is an optional store capability (ports.RunIndex), declared by implementing it. A paired event store that does not is refused explicitly here — never reported as an empty store, which would be a silent capability downgrade.
