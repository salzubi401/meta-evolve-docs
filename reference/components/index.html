    Component contracts

    Status: Shipped.

    Every run is assembled from five replaceable components. This page is the exact contract for each one: the forms meta.run accepts, what the component receives when it is called, every return form that is allowed, how each return is normalized, and which typed failure a violation produces. The Shipped API reference documents the individual types; this page documents the seams between them.

    One rule spans all five contracts. Failures are values, not scores: a component that cannot do its job returns (or is translated into) a typed failure from meta_evolve.domain — see the typed failures entries — and the record keeps "measured badly", "produced garbage", and "crashed" distinct forever.

    Proposer

    The component that creates candidate content — and the only authority it has. Accepted forms for run(proposer=...):

    Form When to use it
    def propose(parent, context) — a plain callable Almost always
    An object with propose(parent, context) A configured proposer type
    A registered ComponentRef Durable runs that must resume elsewhere
    A PatchProposer or other runner Repository proposers needing a workspace

    An object offering both shapes is resolved in that order: a proposer component plus callable execute makes it a runner; otherwise propose takes precedence over __call__.

    Receives. The decoded value of the parent artifact chosen by search, plus a ProposerContext carrying the five things a proposal is authorized to see: a deterministic per-trial rng, the logical step, the task's objectives, the pushed context bundle, and — only when the run declared PullAccess — an audited experience reader.

    May return.

    Return Normalized to
    Any candidate value ProposalResult(candidate=value) — encodability is checked by the task's codec
    A ProposalResult Passed through; the way to attach usage, evidence, a hypothesis, or derived_from
    A typed failure (e.g. ProposerFailure) ProposalResult(failure=...) — an honest "no candidate"

    Failure translation. An exception raised inside the callable becomes a typed ProposerFailure (infrastructure faults and CapabilityError escape instead). A returned EvaluatorFailure, a ProposalResult whose usage claims trials or evaluations, or an unencodable candidate each become InvalidOutput.

    Optional hook. A proposer may define validate_run(*, artifact_kind, artifact_representation, objectives, budget, experience) to reject an incompatible run before any budget is spent.

    The patch variant. PatchProposer wraps a callable (tree, context) that returns a TextPatch or PatchResult. The adapter materializes the parent SourceTree into a private mutable workspace, applies the patch only when its expected bytes match the parent exactly, and captures the result as an immutable successor.

    Evaluator

    The component that defines "better", owned by the task so the proposer can never influence it. Accepted forms for Task(evaluator=...): a plain callable taking the decoded candidate, an object with evaluate(candidate), or a registered ComponentRef.

    Receives. The decoded candidate value, nothing else — an evaluator measures the artifact, not the run.

    May return.

    Return Normalized to
    A finite non-boolean number {objectives[0].metric: value} — allowed only when the task has exactly one objective
    A mapping of metric names to numbers The evaluation's metrics
    An EvaluationResult Passed through; the way to attach evidence, uncertainty, or usage
    A typed failure (e.g. EvaluatorFailure) EvaluationResult(failure=...) — an honest "no measurement"

    Every successful result must cover the metric of every task objective; a missing metric, a return matching no accepted form, a number under multiple objectives, or a returned ProposerFailure each become a typed InvalidOutput. An exception raised inside the callable becomes a typed EvaluatorFailure (infrastructure faults and CapabilityError escape).

    Optional hook. An evaluator may define validate_task(task), called when the Task is constructed, to reject incompatible tasks early. CommandEvaluator — which grades a SourceTree by running an external process under a declared ProcessSpec and EvaluationEnvironment — is the reference implementation of the full contract.

    Search program

    The component that owns selection, admission, and stopping — never candidate content, evaluation, or budget accounting. The shipped presets are Greedy, BestOfN, and Population; a custom program implements one method:

    def next(self, state: SearchState) -> TrialSpec | ArchiveUpdate | Stop: ...

    Receives. A SearchState — the immutable projection of everything committed so far. Programs usually read its derived properties: task, incumbent_id / incumbent_value, archive_members, usage, remaining_budget, objective_satisfied, budget_exhausted, failed_outcomes, failed_evaluations, and — for authoring the next decision — next_logical_step and randomness (the deterministic seed source for a trial).

    May return. A TrialSpec naming the parents, proposer, per-trial budget, and random seed for one attempt; an ArchiveUpdate recording an archive membership transition (spends nothing); or a Stop with a recorded reason. The presets stop with "objective_satisfied", "trial_limit_reached", "budget_exhausted", or (Population only) "population_empty".

    The preset contract. Beyond next, a durable, comparable policy also declares a policy reference, a bind(proposer, budget) step performed by run, a configuration mapping, and an identity_key. Using an unbound preset raises UnboundSearchProgram.

    Context policy (push)

    The application-chosen component that decides what a proposer gets shown. Declared per run as run(context=...); the shipped policies are AncestorsOnly, BestSibling, and NoMemory (the explicit spelling of the default). The protocol is ContextPolicy:

    def select(self, task, candidate, graph, spec) -> ContextBundle: ...

    Receives. The task (for objective-aware selection), the candidate trial reference about to propose, the read-only experience graph, and the declared ContextSpec bounds — max_records (default 20) and max_chars (default 8,000).

    Must return. A ContextBundle whose usage counts exactly match its records and rendering. The kernel independently rejects a bundle that selects anything other than authorized records committed strictly before the proposing trial, exceeds the declared bounds, or reorders the canonical record order — a policy cannot smuggle the future into a proposal.

    Experience reader (pull)

    The audited query capability a proposer receives instead of being handed records. Declared per run as run(experience=PullAccess(...)), whose bounds (max_operations, max_results, max_records, max_chars) apply per trial. The proposer reads context.experience, an ExperienceReader with five operations:

    Operation Question it answers
    search(record_kinds=..., failure_kinds=..., ...) Which prior records match these filters?
    open(ref) What exactly does this record say?
    ancestors(trial_ref) What chain led to this trial?
    siblings(trial_ref) What else was tried from the same parent?
    compare(left_trial_ref, right_trial_ref) How do two prior trials differ, metric by metric?

    Every operation observes only records committed strictly before the proposing trial, is recorded in the run's audit stream, and counts against the declared bounds. Exceeding a bound raises ExperienceBudgetExhausted; an unauthorized or unknown reference raises the deliberately opaque ExperienceAccessDenied. A proposer that used what it read should declare the influencing references in ProposalResult(derived_from=...).

    Where the contracts are enforced

    Normalization and translation live in the callable adapters (adapters/proposers.py, adapters/evaluators.py), bundle validation in the kernel (domain/context.py), and reader auditing in the application layer — component authors never call any of it directly. The Build your own chapter sequences which seam to replace first; the Shipped API reference documents every type named here.
