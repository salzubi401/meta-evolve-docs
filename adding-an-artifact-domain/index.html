    Adding an artifact domain

    Status: Shipped.

    meta.run optimizes whatever you can encode. A domain is one (kind, representation) pair plus the codec that translates between the Python value your proposer and evaluator handle and the durable payload the kernel commits. Adding one takes four small pieces and no change to the library: the coordinator has no branch per domain, which tests/test_four_domain_kernel.py proves by driving number, text, repository, and skill-set runs through one meta.run call site and asserting the same kernel record for all four.

    Piece What it is Shipped example
    Value type what proposers and evaluators see; declares KIND and REPRESENTATION meta.Text
    Codec encode value → payload, decode payload → value TextCodec
    Registration Registry.register_artifact_type(codec) built-in codecs skip this
    Declaration Task(artifact=YourType)

    Text is the smallest complete instance and is worth reading first: the value type and its codec are about fifteen lines each. This page builds a second domain — recipe, an ordered list of instruction steps — the same way.

    The contracts themselves are canonical elsewhere and are not restated here. ArtifactCodec owns the codec laws, the programming model owns Task, Registry, and meta.run, and the architecture owns what artifacts, kinds, and representations mean.

    Every Python block below is one script, run end to end by tests/test_add_a_domain_tutorial.py.

    0. Kind and representation

    The kind names the schema — what a payload means. The representation names the storage shape that payload is written in. The two are separate because kinds can share a representation: source-tree and skill-set are both utf8-tree-v1, the same portable tree bytes read under different rules. The kind, never the bytes, decides which codec reads a committed payload.

    import meta_evolve as meta

print("built-in text domain:", meta.Text.KIND, meta.Text.REPRESENTATION)

    1. The value type

    Declare KIND and REPRESENTATION as strings on the type; Task(artifact=...) reads exactly those two attributes and nothing else, so a plain class works and no base class is imposed. Subclass whatever Python shape the domain already is — Text is a str, Recipe is a tuple.

    Rules that decide whether a value is one of these belong here, in the constructor. Rules about whether a value is any good belong to the evaluator.

    from typing import ClassVar


class Recipe(tuple):
    """An ordered sequence of instruction steps."""

    KIND: ClassVar[str] = "recipe"
    REPRESENTATION: ClassVar[str] = "json-steps-v1"

    __slots__ = ()

    def __new__(cls, steps=()):
        steps = tuple(steps)
        if not all(isinstance(step, str) and step.strip() for step in steps):
            raise ValueError("every recipe step must be non-blank text")
        return super().__new__(cls, steps)

    2. The codec

    encode and decode must be pure, deterministic, and free of I/O, and decode is the only validation entry point — a codec has no separate validate. Return any payload freeze accepts: None, bool, int, finite float, str, lists and tuples of those, and string-keyed mappings of those. Artifact freezes what you return and derives the content digest from it, so codecs never mint or check identity.

    Refuse a value that is not yours by raising TypeError or ValueError. Those two are the rejection signal and nothing else is: encode is reached by every proposed candidate as well as by the seed, so a refusal there fails that one trial as a typed InvalidOutput and the run continues, while any other exception is treated as a bug in the codec and propagates.

    class RecipeCodec:
    """Translates ``Recipe`` values to and from their durable payload."""

    kind = Recipe.KIND
    representation = Recipe.REPRESENTATION
    interfaces = ("ordered-steps/v1",)

    def encode(self, value):
        if not isinstance(value, Recipe):
            raise TypeError("recipe tasks require a Recipe value")
        return tuple(value)

    def decode(self, payload):
        return Recipe(payload)

    interfaces names what a consumer may rely on, independently of the kind, so a later artifact carrying the same structure can declare the same interface and reuse its consumers. Leave it () when nothing consumes the domain structurally yet. kind, representation, and every interface name are identity declarations: each must be non-empty and have no outer whitespace. Registration rejects invalid declarations rather than trimming them.

    3. Register the codec

    registry = meta.Registry()
registry.register_artifact_type(RecipeCodec())
print("declared interfaces:", registry.artifact_interfaces("recipe", "json-steps-v1"))

    Registration is keyed by (kind, representation). The four built-in keys are not overridable — changing the decode of an old key would change the meaning of every artifact already committed under it — so a different behavior needs a different key. A new representation of a built-in kind is a different key and registers normally.

    4. Declare it on the task and run

    Pass the registry to meta.run and name the value type on the task. From here nothing is domain-specific: the proposer receives decoded values and returns one, the evaluator scores one, and search, budgets, lineage, and experience behave exactly as they do for integers.

    def add_step(parent, context):
    return Recipe((*parent, f"step {len(parent) + 1}"))


def score(candidate):
    return {"score": float(len(candidate))}


run = meta.run(
    task=meta.Task(
        evaluator=score,
        artifact=Recipe,
        budget=meta.Budget(evaluations=4, trials=3),
    ),
    seed=Recipe(("preheat the oven",)),
    proposer=add_step,
    search=meta.Greedy(max_trials=3),
    registry=registry,
)

best = run.best()
print("committed as:", best.kind, best.representation)
print("decoded type:", type(best.value).__name__)
print("best value:", tuple(best.value))
print("primary score:", run.summary().primary_score)

    built-in text domain: text utf8-text-v1
declared interfaces: ('ordered-steps/v1',)
committed as: recipe json-steps-v1
decoded type: Recipe
best value: ('preheat the oven', 'step 2', 'step 3', 'step 4')
primary score: 4.0

    That is the whole domain. The script imports meta_evolve and the standard library, and touches no library file.

    5. Check the codec against the published suite

    meta_evolve.conformance.ArtifactCodecTests checks both round trips, repeated-call stability within one process, common file/socket entry points, TypeError/ValueError rejection, and identity-free payloads. The I/O patches are tripwires, not proof of arbitrary purity, and repeated calls do not prove cross-process reproducibility. Subclass the suite and override three fixtures; the conformance section of the programming model has the snippet and the install extra. RecipeCodec above is checked that way in this tutorial's own test.

    What a registered domain does not get yet

    • Restart-resumable execution. mode="durable-local" fails closed with CapabilityError for any task whose (kind, representation) is not one of the four built-in keys. A registered codec is a live object rather than registered source, so it carries no manifest and a resumed run could not verify that the code rebuilding a payload is the code that wrote it. Custom domains are local mode in Milestone 7. They may still use durable storage: after reopening the storage and reconstructing the registry, inspect one through meta.Run(run_id, storage, registry=registry). This is decoding only, not resume or execution authority; command-line inspection remains built-in-only.
    • A published conformance suite for every component. Codecs and repository-editing proposers are published; evaluators, search policies, context policies, workspaces, and sandboxes are not. See meta_evolve.conformance for the current list.
